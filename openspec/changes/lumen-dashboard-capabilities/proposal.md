# Lumen dashboard capability completion

## Goal
Complete the user-reported model-registry, media execution, persistent work-log, MCP personal/organization connection, system-administrator readback and safe chat VM-creation paths across Afterglow and Lumen.

## Required behavior
- Embedding models can be discovered, selected and priced without media/output settings leaking into their payloads.
- Media readiness names the actual scanner/storage, transport or price blocker. Approved managed scanning must be qualified before enabling the routes.
- Chat shows preparation, live public progress and permissions, then one reopenable completion summary whose persisted public steps and UTC timing survive history reload.
- The MCP gallery covers registry templates and clearly separates remote connections from sandbox-managed profiles. Personal credentials remain personal; organization credentials are managed only by verified exact-domain managers or unrestricted human system administrators.
- System-admin changes are visible immediately despite stale native computed-assignment enumeration. Candidate hints cannot confer authority or defeat last-admin protection.
- Cloud mutation requires the existing project-bound manage consent, explicit resource parameters, current native authority and a durable human approval. No live VM is created as a test.

## Authorization and operational scope
The owner approved qualified Lumen/Afterglow publication and rollout, managed ClamAV configuration, coordinated protocol-v2 activation, and at most 1 USD of calls using already registered models/prices/provider credentials. Separately, the owner approved inspecting and requalifying the existing Lumen Kubernetes cluster with a dedicated namespace, minimal RBAC and temporary test Pods. New VM/cluster provisioning and node changes require separate approval. Existing keys, data, scopes and shared load-balancer services must be preserved.

## Companion work
Lumen owns migration 033 and service-side MCP/domain authority, cloud approvals, encrypted checkpoint recovery, history projection and scanner role. Afterglow owns the authenticated BFF, model/settings/work-log UI and system-admin reader fix. The dirty shared Lumen Drover-managed-sandbox branch is not part of this change.

## Evidence boundary
Focused unit tests, real disposable databases, local BFF/service HTTP and synthetic identity/provider transports are recorded separately from actual production configuration, user OAuth, provider billing and sandbox runtime acceptance. Cards and source flags are not proof of execution availability.
