# 마우스 휠 확대·축소와 휠 버튼 화면 이동

## 문제

### 1. 휠을 굴려도 확대되지 않는다

`isMouseWheel` 이 `wheelDeltaY` 가 120 의 배수가 아니면 **전부 트랙패드로** 떨어뜨렸다.

```ts
const notch = e.wheelDeltaY;
if (typeof notch === 'number' && notch !== 0) return Math.abs(notch) % 120 === 0;
return false;   // 근거 없음 → 트랙패드
```

120 배수 정규화는 Windows·Chrome 의 **표준 노치** 이야기다(노치당 `deltaY` 가 100 이어도
`wheelDeltaY` 는 120). 고해상도 휠(자유 회전 마우스 등)은 한 노치를 잘게 쪼개 보고하므로
`wheelDeltaY` 가 120 배수가 아니고, 그 결과 휠을 굴리면 확대 대신 **화면이 움직였다**.

`wheelDeltaY` 는 비표준이라 아예 없을 수도 있는데, 그 경우도 `return false` 로 트랙패드였다.

### 2. 휠 버튼으로 화면을 옮길 수 없다

`onDown` 이 `e.button !== 0` 이면 즉시 반환해 가운데 버튼을 통째로 버렸다. 브라우저 기본
자동 스크롤 위젯만 뜨고 캔버스는 반응하지 않았다.

## 해결

### 휠 판정

120 배수와 줄·페이지 단위 델타는 **확정 증거로만** 쓰고, 트랙패드 표식(가로 성분·소수점
델타)이 하나도 없으면 마우스 휠로 본다. 남는 애매함은 크기로 가른다 —
`MOUSE_WHEEL_MIN_DELTA`(10px). 트랙패드의 느린 두 손가락 스크롤은 한 자릿수 픽셀로 들어오고,
휠은 고해상도라도 노치 조각이 그보다 크다.

트랙패드 두 손가락 스크롤의 화면 이동은 그대로 두었다. 관성 스크롤을 확대로 오판하면 뷰가
크게 튀므로 그 경로를 없애지 않는다.

### 휠 버튼 드래그

`Gesture` 에 `panOnly` 를 추가해 가운데 버튼 시퀀스를 이동 경로로만 보낸다.

- 노드·존·엣지 대상 해석을 건너뛴다 → 노드 위에서 눌러도 노드를 잡지 않는다
- `onEnd` 에서 즉시 반환한다 → 움직이지 않고 떼도 선택·선택 해제를 하지 않는다
- 연결 핸들(`data-link-handle`) 분기도 건너뛴다
- `mousedown`·`auxclick` 에서 기본 동작을 막는다 — `pointerdown` 의 `preventDefault` 만으로는
  Windows·Linux Chrome 의 자동 스크롤 위젯이 막히지 않는다

## 확인할 수 없었던 것

사용자의 실제 마우스가 어떤 `deltaY`/`wheelDeltaY` 를 보고하는지는 관찰하지 못했다 — 브라우저
팬은 에이전트 쪽 환경이라 물리 휠을 돌릴 수 없다. `MOUSE_WHEEL_MIN_DELTA` 10px 는 "트랙패드
느린 스크롤은 한 자릿수, 휠 노치 조각은 두 자릿수" 라는 **가정**이며, 이 경계는
`wheelIntent.test.ts` 에 장치 프로파일로 고정해 두었다. 실제 장치에서 여전히 어긋나면 이 상수
하나만 조정하면 된다.
