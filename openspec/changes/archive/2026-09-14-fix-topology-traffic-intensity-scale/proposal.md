# 토폴로지 트래픽 강도 스케일 교정과 중복 트렁크 배지 제거

## 왜

토폴로지 캔버스는 "어떤 네트워크가 얼마나 바쁜가"를 한눈에 읽으라고 만든 화면인데, 그 인코딩이 실환경에서 작동하지 않는다.

**측정(2026-09-13, 운영 Prometheus, 윈도우 2m, NIC 시계열 43개)**

- rx+tx 중앙값 **8,729 bps**, 최대 **365,770 bps**
- 강도 스케일 하한 `1e5` 이상은 **4 / 43 (9%)**
- `edgeIntensity(bps < 1e5)` 는 `{width: 1.5, opacity: 0.40}` 을 돌려주는데 이는
  `bps == null`(텔레메트리 없음) 스타일과 **완전히 동일**하다 →
  **살아 있는 케이블 39개가 "계측 없음"과 구분 불가능하게 그려진다.**
- 실제로 화면에 나타나는 굵기는 `{1.5, 2.06, 2.13, 2.28}` (범위 1.5~3.5 중 사실상 2단계)
- `width = Math.max(2.5, width)` 때문에 **모든 트렁크가 정확히 2.5px** 이다.
  3-tier 트렁크(467k)조차 계산값 2.34 가 2.5 로 깎인다 → 트렁크 굵기는 정보를 0 비트 싣고
  있으면서 가장 바쁜 케이블(2.28)보다 항상 굵다(시각적 위계 역전).
- `FLOW_MIN_BPS = 1e5` 라 흐름 점도 4/43 에만 붙는다.

**중복 배지 (Neutron 실측, 라우터 30개 전수)**

tenant 망을 2개 이상 무는 라우터가 **0개**다(`private_provider` 27개 · `public_provider` 3개 전부
tenant 망 0~1개). `trunkNetIds()` 정의상 uplink 배지(`하위망 합산`)와 tenant 배지(`네트워크 합산`)는
라우터가 tenant 망을 하나만 물면 **같은 배열 → 같은 값**이다. 실제로 `231k/236k` 이 배지 2개와
스위치 카드까지 3번 반복되고, 그 배지들이 provider 존의 VM 카드를 덮는다.

## 무엇을

1. 강도 스케일 하한 `1e5 → 1e3`, 구간 3 → 6 decade(1e3~1e9), 굵기 `2.0~3.5 → 1.8~4.5`.
2. `rate != null` 이면 최소 굵기 1.8 을 보장해 **"조용함"이 "계측 없음"(1.5)과 절대 같아 보이지 않게** 한다.
3. 트렁크 굵기 하한 `Math.max(2.5, …)` 제거.
4. 트렁크의 강도 스칼라를 `rx + tx` → `max(rx, tx)` 로 바꿔 east-west 이중 계상을 없앤다.
5. 흐름 점 하한 `1e5 → 1e4`.
6. provider uplink 배지는 `trunkNetIds(e).length >= 2` 일 때만 그린다(값이 실제로 달라질 때만).
7. 레인 뷰 호출부가 "텔레메트리 없음"을 `bps = 0` 으로 뭉개던 것을 null 로 구분한다.

## 무엇이 아닌가

- 백엔드 PromQL·rate 윈도우·집계 의미는 건드리지 않는다. 숫자는 이미 맞다.
- `trunkNetIds` / `isUplinkTrunk` 로직은 유지한다(라우터가 tenant 망을 2개 이상 무는 날 자동 복귀).
- 상대 스케일(현재 뷰 최대값 정규화)은 채택하지 않는다 — 시점 간 비교가 깨져 분석 도구로 부적합하다.
