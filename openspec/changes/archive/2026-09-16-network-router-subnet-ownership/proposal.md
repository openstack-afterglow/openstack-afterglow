# 네트워크·라우터·서브넷 소유권과 연결 제어

## Goal

사용자 네트워크 콘솔에서 프로젝트 소유 네트워크와 라우터만 변경할 수 있게 하고, 라우터와 네트워크 양쪽에서 소유 서브넷을 연결하며, 서브넷 생성 직후 선택한 소유 라우터에 연결할 수 있게 한다.

## Scope

- 네트워크 목록·상세 응답에 `project_id`를 포함해 공유 네트워크의 실제 소유자를 UI가 판정할 수 있게 한다.
- 사용자 API에서 네트워크 서브넷 생성과 라우터 인터페이스 추가·제거가 네트워크/서브넷 소유권을 확인하도록 한다. 외부 게이트웨이 설정은 기존 허용 정책을 유지한다.
- 사용자 네트워크 상세에서는 소유 네트워크에만 서브넷 생성, 라우터 연결 및 연결 해제를 노출한다. 새 서브넷 폼은 선택한 소유 라우터에 생성 직후 연결할 수 있다.
- 사용자 라우터 상세에서는 소유 네트워크와 그 서브넷만 선택해 인터페이스를 추가한다.
- 네트워크 목록의 기본 네트워크·삭제·일괄 선택은 소유 네트워크만 허용한다. 공유 또는 외부 네트워크에는 변경 메뉴를 렌더하지 않는다.
- 튜토리얼 transport도 `project_id`와 소유권 제약을 반영한다.

## Non-goals

- 관리자 API/관리자 토폴로지의 관리 권한 정책을 변경하지 않는다.
- OpenStack의 공유 네트워크 가시성 또는 외부 게이트웨이 정책을 변경하지 않는다.
- 신규 API endpoint를 만들지 않는다.

## Acceptance criteria

1. 공유 네트워크를 보는 다른 프로젝트 사용자는 네트워크 삭제·기본 설정·서브넷 생성·라우터 연결/해제 UI를 볼 수 없고, API 직접 호출도 거부된다.
2. 소유 라우터에서 소유 내부 네트워크를 고른 뒤 해당 네트워크의 서브넷을 골라 인터페이스를 추가할 수 있다.
3. 소유 네트워크에서 여러 서브넷을 만들 수 있고, 생성 폼에서 선택한 소유 라우터에 새 서브넷을 `auto_gateway`로 연결할 수 있다.
4. 목록·슬라이드 패널·직접 상세 경로와 tutorial mock에서 소유권 판정이 일관된다.
5. backend ownership regression tests, focused frontend tests, browser QA, architecture check, and the repository gate pass.
