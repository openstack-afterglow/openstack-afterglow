## Why

The approved full-panel Afterglow glyph rain, ring and reflection scene currently appears only during VM specification preparation; other pending interfaces still use unrelated spinners, shimmer placeholders, dots and text-only waiting states. The owner requests the same visual family at every loading location without changing actual work or cloud behavior.

## What Changes

- Introduce one `LoadingState` primitive with surface, section, inline and control variants, existing localized copy, snippets and safe span semantics.
- Reuse the exact approved renderer for bounded/full-area live scenes and static compact frames, with semantic theme updates and bounded work.
- Migrate initial loading, subordinate lookup, refresh, mutation, streaming/tool preparation and control ornaments across administrator, consumer, identity and AI surfaces while retaining useful already-loaded content.
- Preserve actual measured progress, server-reported steps, errors, cancellation, retry and VM preparation dependency states.
- **BREAKING**: remove the internal `LoadingSpinner`, `LoadingSkeleton` and `ActivityIndicator` components and exports after migrating all callers; no compatibility shim.
- Remove obsolete appearance/source-structure assertions rather than replacing them with new wiring tests.

## Capabilities

### New Capabilities

- `authored-loading-states`: one truthful, accessible, theme-aware authored pending visual across interface scales.

### Modified Capabilities

None. VM creation, authorization, API and native operation requirements remain unchanged.

## Impact

Frontend shared UI primitives, their consumers/routes, loading-related incidental tests, design/architecture/user guidance and changelog only. No backend/API contract, request scheduling, authentication, data schema, cloud permission, deployment or shared database mutation is authorized. Local synthetic/browser verification is separate from live cloud acceptance.
