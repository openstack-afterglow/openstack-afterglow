## Why

인터페이스마다 인바운드·아웃바운드 표가 항상 표시되어 상세 화면이 길다. 표시명 `허용 규칙 (합집합)`보다 사용자 요청의 `적용된 허용 규칙`이 적용 정책을 직접 설명한다.

## What Changes

- 인터페이스별 인바운드·아웃바운드를 독립 접기/펼치기로 제공하고 초기에는 접는다.
- 기존 `Button` disclosure 패턴과 `TableShell`을 재사용하며 버튼의 확장 상태와 명확한 펼치기/접기 이름을 제공한다.
- 제목·접근성 영역명·조회 실패 안내에서 합집합 용어를 사용자 표시명으로 바꾼다. 내부 규칙 계산 이름과 데이터 계약은 유지한다.
- 접힌 상태에서도 조회 오류·누락·미적용 안내는 숨기지 않으며 데이터 갱신은 사용자의 방향별 펼침 상태를 유지한다.

## Capabilities

### New Capabilities

없음.

### Modified Capabilities

- instance-security-group-union: 방향별 독립 disclosure와 적용된 허용 규칙 표시명.

## Impact

공용 인스턴스 상세 표시 컴포넌트와 관련 소비자 테스트·문서만 변경한다. 규칙 정규화·저장·polling·backend/API·권한은 변경하지 않으며 기존 서버 cache 최신성 한계를 해결했다고 주장하지 않는다. 직접 상세·목록 패널·관리자 공용 상세가 동일 컴포넌트를 사용한다.
