# Afterglow Design System

## Product character & authority

Afterglow is a dark-first cloud operations console: neutral graphite surfaces support dense operational work, warm orange identifies the single highest-priority affirmative action, and blue/purple remain reserved for data and semantic information. Light mode remaps the same semantic hierarchy; it is not a separate brand.

New UI follows this authority order: `frontend/src/routes/layout.css` owns theme and runtime CSS values; `frontend/src/lib/design/tokens.ts` exposes TypeScript metadata; `frontend/src/lib/components/ui` owns reusable behavior and markup; feature routes and components compose those primitives. `:root.light` legacy palette overrides are a compatibility boundary for existing visual debt, never a new API.

Branding defers to content. Inside the authenticated console the global header owns one 24px `/afterglow-symbol.svg` slot next to the site name, followed by project selection. It carries neither an Admin badge nor a route breadcrumb, and no sidebar border extends through the brand row. The open global navigation drawer replaces that visible brand row with its own close/brand row; service sidebars carry the current page name, never a second brand. No route spends `PageShell` space on brand-only content. Unauthenticated entry routes retain `LoginBrandHeader` and existing configured asset precedence; administrative previews and third-party provider marks are outside this single-visible-slot rule.

Built-in logo slots use `/afterglow-logo.svg`; favicon uses `/favicon.svg`. The wordmark is outlined from bundled Pretendard Latin (Inter-derived), so installed fonts cannot alter its width. Its actual artwork has 36-unit margins on every side in `viewBox="0 14 533.02 180"`; the supplied symbol and favicon retain their already-equal horizontal margins. Embedded dark-mode SVG styling is paired with explicit `color-scheme` on login images and theme-dependent admin previews. Responsive login sizing preserves aspect ratio and centers the entire image without stretching. These built-in SVG assets do not expand the raster-only administrator upload contract.

## Apple HIG adoption and non-goals

Afterglow borrows Apple's interaction behaviour, not Apple's visual system. The reference is the local Human Interface Guidelines copy in the `apple-design` skill (`~/.claude/skills/apple-design/references/hig/`); cite a rule as `file.md › Heading` when a review turns on it. A web application takes Apple's principles and foundations — accessibility, layout, typography, writing — plus the desktop conventions lens of pointer, keyboard, and multi-pane hierarchy; it does not take the iOS touch-platform conventions.

Apple's eight principles are the first review filter, and a surface that breaks one has a larger problem than any single rule it breaks: purpose, agency, responsibility, familiarity, flexibility, simplicity, craft, delight. Afterglow is a dense operations console, so ties break toward simplicity and familiarity. Every conclusion is a review finding naming the `frontend/src/lib/components/ui` primitive or the rule in this document at fault; a contrast or hierarchy complaint stays a finding and never authorizes changing an existing `--color-*` value in `layout.css`.

These parts remain Afterglow's own vocabulary rather than Apple's visual system: the global navigation drawer and collapsible service sidebar, the `:root.light` remap, the Pretendard/IBM Plex Korean stack, warm `Button variant="primary"` CTA, operational status tones, usage meters, topology domain colors, Palimpsest layer surfaces, and `ChatBubble`. Generic interaction principles apply without restyling these surfaces into Apple components.

These parts of the HIG are deliberately not adopted, and no rule in this document may be read as authorization for them.

| Not adopted | Reason |
| --- | --- |
| Apple palettes, system colors, and contrast-driven changes to existing token values | The dark-first graphite and warm-orange system above is the product's identity and is to be preserved, warm `primary` emphasis included. A contrast shortfall is a finding against this document. Adding a new token still follows the New UI entity workflow. |
| Liquid Glass or any material inside the content layer | `materials.md › Liquid Glass`: "Don't use Liquid Glass in the content layer." `Card`, `TableShell`, `StatTile`, and form surfaces stay `1px solid var(--color-line)` with no shadow; only modal/popover elevation carries a restrained shadow. |
| `dark-mode.md`'s "no app-specific appearance switch" | Afterglow ships the `:root.light` remap and keeps it. |
| SF Pro, SF Compact, New York, and SF Symbols as families | Typography is locally hosted Pretendard and IBM Plex with no runtime font CDN. The principle that survives is one icon system whose weight matches adjacent text. |
| Title-style capitalization for buttons, menu items, and titles | The console is Korean. |
| Tab bars as top-level navigation | Top-level navigation uses the hamburger-controlled global drawer; detailed routes use their collapsible 15rem service sidebar. |

Materials are admitted on one layer only, and membership is decided by one test: **does content actually pass beneath the surface?** A blur that samples a flat canvas or an interposed scrim produces no depth cue and only costs a compositing layer. Apple confines Liquid Glass to "a distinct functional layer for controls and navigation elements ... that floats above the content layer" and directs you to "use Liquid Glass effects sparingly" (`materials.md › Liquid Glass`), so the adopted set is deliberately short.

`--material-chrome-alpha` (`90%` dark, `85%` light) with `--material-chrome-blur` `1.125rem` belongs to the application header alone, which is `fixed` at `top: 0` while the main scroller starts at the same origin, so page content genuinely scrolls under it. The header carries it on an `inset-0` child at negative z-index rather than on the `<header>` itself, because a non-`none` `backdrop-filter` makes an element a containing block and would trap the header's own popovers. `--material-overlay-alpha` (`94%` dark, `90%` light) with `--material-scrim-blur` `0.75rem` belongs to `BulkSelectionOverlay`, the one control-layer surface with rows streaming beneath it. `--material-scrim-blur` alone belongs to the full-viewport scrims of `Modal`, `CmdPalette`, `ConfirmDialog`, and the admin evacuate/recovery dialogs, replacing four ad-hoc radii. `MATERIAL_CSS_VAR` exposes all four names. The alphas are set so the header stays readable at its worst composite — a dark glyph scrolling directly beneath it — which measures `#d6d7d9` in light (`--color-ink-0` 12.18:1, `--color-ink-1` 8.50:1, `--color-ink-2` 4.73:1) and `#2b2c2e` in dark (16.47 / 12.47 / 6.60 over canvas, 12.72 / 9.62 / 5.09 under a glyph). Light is the binding case and `--color-ink-2` is the binding token, so a light alpha below 85% or a darker `--color-ink-2` would drop header copy under AA; re-measure both whenever the light ramp moves.

These surfaces are excluded on evidence, not oversight. The service sidebar begins below the global header and its main scroller starts at the sidebar's right edge, so content never passes beneath it. The global navigation drawer sits above a scrim, which already flattens the backdrop. `Modal`, `SlidePanel`, and `CmdPalette` keep opaque panels and blur only the scrim. `ActionMenu` remains opaque until its hover treatment no longer derives from opaque `--color-surface-sunken`.

The opaque background is the base declaration and translucency is the enhancement, so an unsupported browser, `prefers-reduced-transparency`, and `forced-colors` all fail safe to a solid surface. Those three blocks carry equal specificity, so source order is the contract — the accommodations must follow the `@supports` block or they are silently overridden — and `designSystemRules` pins that order. `Card`, `TableShell`, `StatTile`, and form surfaces stay opaque always. A material carries depth, never state.

The light ramp is derived from the dark theme, not from a framework's default scale — but the axis it borrows is chroma, not hue. Measured in OKLCH, the previous light neutrals already sat in dark's own hue band (light `#0f172a`/`#475569` at H 258-266, dark `#101113`/`#999ca5` at H 264-271); what made them read as a stock slate template was carrying 2.4-6.9x dark's chroma at that hue (`--color-ink-0` C=0.0398 against dark's 0.0013). The ramp now holds H 262-286 and cuts chroma to dark's envelope (C 0.0013-0.0154), so the reduction falls almost entirely on the ink, where it was tinting body copy blue, and barely touches the surfaces, which were already near-neutral. A warm ramp was tried first and rejected on sight as sallow: at L above 0.95 a near-zero chroma leaves hue under-determined at 8-bit, so "almost neutral" drifts to whatever rounding produces, and it landed at H 68-91. The surfaces therefore carry a deliberate chroma floor (0.0013-0.0055) in the cool direction rather than aiming at zero. Warm is unchanged in both themes: it is the identity anchor, and a palette revision is not licence to move it. Every chromatic token keeps full strength (C 0.076-0.200), so the neutrals losing their cast makes the orange read hotter, not the console flatter.

The light surface tiers are now distinct — `canvas` `#f2f3f6` -> `base` `#f7f8fa` -> `raised` `#fefeff`, OKLCH lightness steps of 0.015 and 0.018 — where they previously collapsed to 1.03:1 and 1.00:1 and left depth to hairlines alone. `--color-line-2` moved from `#cbd5e1` to `#7c8089` (3.72:1 on `base`, 3.57:1 on `canvas`, 3.44:1 on `sunken`), and the light `input`/`textarea`/`select` override, which had pinned those controls to `#ffffff` on a `#cbd5e1` border at 1.48:1, now reads the tokens — that override, not the token, was where SC 1.4.11 actually failed. Every neutral entry in the light legacy-override block is a `var(--color-*)` reference rather than a literal, so the ramp is the single source of truth and the two halves of the theme cannot drift to opposite temperatures again.

Warm has two tokens because one cannot do both jobs: `--color-action-warm` is the fill and border, where `--color-action-on-warm` sits on it at 4.94:1, and `--color-warm-text` is the copy, which reaches 4.87:1 on a light surface where the fill value gives only 3.35:1. Never paint text with `--color-action-warm`. Every semantic tone follows the same split. An action colour must be declared inside `@theme static`, not `:root`: Tailwind generates a utility only from a `--color-*` name declared there, and a name declared elsewhere silently produces no rule at all.

`--color-ink-3` is disabled text and nothing else, and the application now holds to that: the only remaining uses are the `disabled:` variant and `::placeholder`/`:disabled` rules in scoped CSS. It measures 4.42:1 on the light base and 3.29:1 on the dark base, so any content painted with it fails SC 1.4.3 — that is why the rule is absolute rather than a preference. A section label, a username, an empty-state sentence, a record count, a meter's own readout and a placeholder are all information, and all take `--color-ink-2`.

Use `SURFACE_CSS_VAR` rather than spelling surface variables in TypeScript-driven styles. Selection uses `SURFACE_CSS_VAR.selected`, never a filled blue/purple navigation treatment. Modal/dialog shells use `bg-surface-scrim`; drawers and sidebars use `bg-surface-scrim-soft`. `ConfirmDialog` intentionally keeps its canvas wash (`color-mix(in oklab, var(--color-surface-canvas) 72%, transparent)`) because it is not a black scrim.

Map legacy colors by role: gray/slate becomes surface, ink, or line; blue/purple become data or semantic information; green becomes success; red becomes danger; yellow/amber becomes warning; orange becomes warm. Small orange copy in light mode uses `--color-warm-text`, not raw warm. Do not collapse rose, indigo, cyan, sky, or teal into a generic tone: introduce a semantic token and primitive first when required. `CHART_COLORS`, topology external/shared/internal/internal-2/router/link/gateway colors plus the canvas zone-fill alpha (`--topology-zone-fill-alpha`, `--topology-zone-fill-alpha-active`) and grid tokens (`--color-topology-grid-minor`, `--color-topology-grid-major`), and GitLab `#FC6D26`/`#E24329` are domain or third-party-brand exceptions only.

### Type, spacing, geometry, and elevation

Typography has three explicit roles and no feature may redeclare a Korean-only font family. `--font-sans` is locally hosted Pretendard Variable for Korean body copy, controls, tables, and dense console UI. `--font-display` is locally hosted IBM Plex Sans KR for public-page hero, section, and editorial headings only; do not use it for ordinary console page titles or controls. `--font-mono` is locally hosted IBM Plex Mono followed by Pretendard, so identifiers and code remain technical without making ordinary timestamps or status copy harder to scan. All bundled fonts use WOFF2 and `font-display: swap`; do not add a runtime font CDN dependency.

For `html:lang(ja)` and `html:lang(zh-CN)`, the sans/display roles use Latin-only aliases of those bundled faces (restricted `unicode-range`) followed by language-appropriate system CJK fonts: Hiragino/Yu Gothic/Noto Sans JP, or PingFang/Microsoft YaHei/Noto Sans SC. Mono uses IBM Plex Mono plus the same CJK fallback family. Never copy a Korean font into either CJK stack: kana and Han characters must use consistent Japanese/Chinese forms. No new font downloads are required; exact CJK metrics depend on installed system fonts.

Editorial line breaking follows language too: Korean retains `keep-all`; Japanese and Chinese use normal CJK line breaks. Long translated headings must wrap within their container, including emphasized hero text; do not retain Korean-only `white-space: nowrap` on translated phrases. The landing surface uses `overflow-wrap: anywhere` as a last resort for long unbroken words.

Console body/form copy is `0.875rem`/400. Resource rows, navigation, and buttons are `0.8125rem`/500. Support labels, status, and metadata are at least `0.75rem`; only identifiers and code use mono. Page titles are `1.25rem`/600 with `1.75rem` line-height. Breadcrumbs are ordinary-case `0.75rem` muted text with tight tracking. Quotas, metrics, and timestamps use tabular figures. Body copy keeps a relaxed line-height; dense labels use 500 or 600 rather than synthetic bold. Update this document before adding another type size or role.

`PageShell` owns the outer content box on ordinary console data/settings pages: `width: 100%`, `max-width: var(--app-content-max-width)` (`80rem`), `min-width: 0`, and `margin-inline: auto`. The Lumen chat workspace is the full-bleed exception described below. Route padding is uniformly `1rem` mobile and `1.5rem` tablet/desktop; there are no route-specific max-width or dense variants. Nested detail/workspace components must not add a second outer width or padding. Dialogs, readable articles, chat transcripts, and individual cards may retain their own inner limits. The spacing rhythm is 4px. Radius is token-backed. `--radius-sm` `0.25rem` and `--radius-md` `0.375rem` are the control tier, `--radius-lg` `0.625rem` is ordinary panels, cards, and tables, `--radius-xl` `0.875rem` is dialogs, and a literal `999px` capsule stays reserved for status pills, avatars, and meters. These four override the Tailwind scale that `rounded-sm`/`rounded-md`/`rounded-lg`/`rounded-xl` resolve against, so geometry retunes in `layout.css` instead of across feature files, and `RADIUS_CSS_VAR` exposes the same names to TypeScript. Tier by rendered size, not by role name: a control under roughly 32px takes `--radius-md`, because at the panel radius a 26px row-action button reads as a capsule and stops being separable from a `StatusChip`. Ordinary surfaces use `1px solid var(--color-line)` with no shadow; required interactive boundaries use `--color-line-2`. Only the floating layer carries elevation, through three tokens exposed as `ELEVATION_CSS_VAR`: `--shadow-restraint` for unanchored dialogs and panels, `--shadow-popover` for a surface anchored to the trigger it must stay attached to, and `--shadow-overlay-compact` for an unanchored surface under `20rem` wide, where the deep ambient layer overshoots the element casting it. Each is defined in `:root` with its own `:root.light` alpha, because a dark shadow reused on white reads as grime rather than depth. A `var()` naming an undefined token computes `box-shadow: none`, so an elevation token is never referenced before it is defined. Primary actions are flat warm fills without gradient or glow. Focus is `--focus-ring = 0 0 0 2px var(--color-surface-base), 0 0 0 4px var(--color-line-2)`; removing an outline is allowed only when the same visible ring replaces it, with a native outline fallback in forced-colors mode.

Account MCP setup uses two adjacent method selectors (OAuth/API key) and renders only the selected method's setup and connection list. The compact personal-key form groups name, read/manage access, and lifetime; custom date input appears only for the custom choice. Whole `mcp.json` copy controls belong to each configuration, with actual secret-bearing JSON restricted to the once-only issuance view. Recent activity exposes 10/15/20-row paging. My Resources uses the same shell with all supported inventory categories: unavailable, denied, disabled, and partially known counts must never look like verified zero. Wide project totals scroll inside a named, keyboard-focusable region rather than overflowing the page.

Each account MCP grant owns a native details disclosure for at most ten observed client signatures. Keep the self-reported/inferred warning visible before expansion; names/versions, inferred software/kind, evidence source, browser/OS and first/last initialization observation belong to the same credential, not separate device/session cards or a live-online badge. Unknown observed identity and no observation are different states. Values wrap on mobile; use existing type/surface tokens without adding chrome.

The native client disclosure and connection-removal control have at least 44px mobile touch height. Desktop actions align with the credential's top edge, never vertically centered beside an individual observed client in the expanded list. Keep the destructive scope at the credential level; native disclosure semantics and existing button tokens remain authoritative.

OAuth and API-key lists publish their own verified rows independently. Failure/pending never paints a verified zero count; show the selected method's inline error and retry while preserving issuance authority guards. `연결 제거` names the credential in confirmation and explains that all clients sharing it lose access. Keep ownership and refresh/method-generation fences through the awaited confirmation; do not offer spoofable per-User-Agent blocking.

### Layering and focus

`layout.css` defines `--app-header-height: 3rem`, `--app-sidebar-width: 15rem`, and `--app-sidebar-collapsed-width: 3.5rem`. `LAYOUT_CSS_VAR` exposes the header, expanded sidebar width, and active `--app-sidebar-offset`: tablet/desktop reserve 15rem when expanded, 3.5rem for the icon rail, or 0 without contextual navigation; mobile frames override the inset to 0. Root chrome derives that offset from route context and independent `sidebarExpanded` state. Fixed panels and Cloud Shell share it. The runtime layer order remains sidebar 30, header 35, panel 40, modal 50, toast 60, confirmation 200, popover 210, command 220. The contextual sidebar uses sidebar; full-viewport global navigation uses modal plus existing `dialogFocus` isolation; root header uses header. Backdrop precedes its panel in DOM order. Feature composition must not trap overlays below shell chrome.

Dialog keyboard traversal excludes controls beneath hidden or inert ancestors, including breakpoint-only footer controls. ProjectSelector portals opened from a drawer stay within its dialog boundary. SlidePanel is an end-aligned, shrinking flex child of the current workspace frame: default caller width/max-width classes remain authoritative, CSS bounds default and saved widths when navigation or viewport geometry changes, and the saved preferred width is not rewritten by that constraint.

### Gradients and chrome

`--gradient-brand` remains logo/brand/editorial decoration. `Button variant="primary"` is a flat warm fill and the single highest-priority affirmative CTA per task surface. `--gradient-usage`, `--gradient-usage-warning`, and `--gradient-usage-danger` remain quantitative bars only. `--warm-soft`/ring and `--accent-soft`/ring are semantic tints; `--admin-tone*` belongs only to admin context. Reuse global scrollbar tokens; do not add component-scoped scrollbar styling.

## Layout & responsive hierarchy

Use the existing Tailwind breakpoints only: mobile is `<768px`; tablet is `md` (`768–1023px`); desktop is `lg` (`≥1024px`). `sm` (`≥640px`) is a compact mobile refinement, not a separate layout tier; use `xl` only to increase density after the desktop hierarchy already works. Do not introduce a component-specific breakpoint without updating this section and its test.

**Mobile (<768px).** Keep existing PageShell padding and single-column resource/form behavior. The global hamburger opens an opaque, dismissible full-height navigation drawer over the existing scrim; closed drawer controls are unmounted. On detailed routes, the owning service group opens to its visible destinations without a duplicate current-page menu row. Both expanded service panels and compact rails are hidden because mobile reserves no service-sidebar workspace width. Project selection and mode switching remain available in the drawer footer. Header and drawer use identical brand/control insets and sizes; the header prioritizes the 24px brand symbol and 44px utility targets, while the wordmark may hide on compact mobile. Tables preserve their existing horizontal-scroll or equivalent route-defined card contract. Mobile SlidePanel remains full-viewport and modal.

`TableShell` is also the positioning containing block for absolute screen-reader-only cell labels. Keep those labels within its horizontal scroll viewport; otherwise off-screen labels can expand the document even when the visible table is correctly clipped. Menus/popovers that must escape the viewport use the existing portal pattern, not an uncontained absolute child.

**Tablet (768–1023px).** Keep existing PageShell padding. The global header spans the viewport and includes brand-adjacent project selection. Search stays reachable through the global drawer and compact header trigger. Overview roots and standalone topology do not reserve sidebar space. Detailed routes show a 15rem contextual sidebar below the header with the current page title and its service destinations; collapsing retains a 3.5rem destination-icon rail. The same top-of-sidebar button switches between collapse and expand, never moving beside the header project selector. PageHeader actions wrap; SlidePanel stays non-modal and follows the current sidebar offset.

**Desktop (≥1024px).** Keep PageShell padding and inline, wrapping PageHeader actions. The full-width header contains hamburger, brand and project selection on the left, viewport-centered resource search, and Cloud Shell before the mode control in the right utility group. There is no header breadcrumb, brand-adjacent Admin badge, or separate service-sidebar reopen control. Project/brand labels truncate before controls overlap. Global navigation is a drawer at every width. Detailed routes retain a contextual sidebar with the current page name at its top-left when expanded and destination icons when collapsed. Overview roots and standalone topology give the workspace the full viewport width; collapsed rails retain only 3.5rem. Fixed panels/docks use the same active offset; changing navigation width never terminates their work.

Header search uses the existing compact trigger at 768–1279px and the viewport-centered input trigger at `xl` (≥1280px). The expanded width reserves room for Cloud Shell, mode switching and Docs together; exactly one search trigger is visible at the 1279/1280 handoff. This is a density refinement, not a new layout tier or a hidden destination.

At every width, group by relationship rather than by leftover space: unrelated controls take their own `Card` group, optionally labeled by `SectionHeader`, instead of one shared control row, so adjacency always means the actions are related. Sibling `Card` and `StatTile` groups in a multi-column layout share one grid definition so labels, values, and control edges align across the row instead of each cell being hand-sized to absorb `PageShell` width. A `TableShell` cell holds one short scannable value; long-form or secondary detail moves to the row's detail route or the shared `SlidePanel`, never into a wider or wrapping cell.

Mode controls always label and icon the current route surface (`사용자 모드` or `관리자 모드`); their link destination, title, and accessible name describe switching to the opposite surface. Mobile and tablet keep the control in sidebar/drawer footers; a collapsed tablet rail still reaches it through the global drawer. Desktop places it in the header. The 1024px handoff must expose exactly one visible control with identical state semantics.

Navigation ownership follows visible declared item routes (exact path or slash-delimited descendants), choosing the longest match so parent paths cannot also select nested destinations. Topology remains a standalone destination despite its Network URL and sits directly after Activity in global navigation. Project settings remain only in the existing ProjectSelector popup. Global group expansion retains manual choices; a newly active service can expand its own group without opening unrelated groups. Contextual collapse keeps destinations and current-page selection in an icon rail; its topmost button expands the same panel without changing project, mode, route, or keyboard focus.

Sidebar and AdminSidebar are capability-aware adapters over one shared `ConsoleNavigation` shell and existing `userNavSections`/`adminNavSections`; the command palette uses the same destination declarations. The drawer has at most group + item levels; deeper resource hierarchy remains route content. The contextual sidebar displays only the current service's visible items. Expanded panels show icons and labels with the selected page title above them; compact rails retain 44px destination targets, accessible names, native label tooltips, active selection, and vertical scrolling through the global scrollbar tokens without horizontal overflow. Their top control stays in the sidebar and changes its collapse/expand action. Global-menu duplicates are absent; existing footer actions stay reachable through the global drawer/header when the rail is compact. Every materially changed destination stays registered in `nav.ts`, with its own required SVG icon path. CmdPalette continues to label its project and user/admin scope because its modal scrim covers background authority controls.

The desktop header search trigger stays within the fixed header height at the 1024px handoff. Its translated caption uses a shrinkable single-line ellipsis; the search icon and shortcut badge do not shrink, and the full translated accessible name remains available. Long translations must not create a taller header control.

## Actions

Use `Button`: `primary`, `accent`, `secondary`, `subtle`, `ghost`, `outline`, `danger`, `danger-outline`, or `link`; and sizes `xs`, `sm`, `md`, `lg`, or `icon`. Warm `primary` is one highest-priority CTA per surface. Blue `accent` is create/save/run and other routine operational work. `secondary`/`outline` are neutral actions; `subtle` compact chrome; `ghost`/`icon` utility actions; `danger`/`danger-outline` destructive entry or confirmation; `link` inline navigation. `href` renders an anchor; a missing/falsy href renders a native button. Icon-only `Button size="icon"` requires `ariaLabel`.

Disabled anchors omit `href`, set `aria-disabled`, and leave the tab order with `tabindex="-1"`; the click handler also blocks navigation. `target="_blank"` anchors always add `noreferrer`, including official billing-console actions. Button has no loading prop: callers compose `disabled` with an accurate label.

`Button ariaPressed` exposes a boolean toggle state on native buttons. Chat's optional native API Search action uses this state and a 44px mobile touch target; built-in search models display a non-toggleable `Search · 기본` state. Capability badges in model lists describe support, not whether search ran on a specific answer.

`Button ariaExpanded` exposes native-button disclosure state. Image upload history uses this control with a visible version count and explicit 보기/접기 label; historical rows retain the same identity and actions when expanded.

Every label says what happens and keeps its name through the flow: a trigger labeled 삭제 leads to a confirmation whose affirmative button is also 삭제, not a generic 확인. `confirmDialog()` in `frontend/src/lib/stores/confirm.svelte.ts` passes only a message today and `ConfirmDialog` hardcodes 취소/확인, so naming the verb first requires extending that store and primitive with an optional confirm label, adding the primitive test, and updating this document.

## Forms

Compose forms with `Field` plus `TextInput`, `SelectInput`, or `TextareaInput`; use `FormModal` and `ConfirmDialog` for submit/cancel flows. `ToggleGroup` owns compact mutually exclusive filter/view choices: callers supply `value`, `options`, and `onchange` rather than recreating segmented controls. Field owns visible label/help/error copy and `for`/`id`; input primitives own placeholder, disabled, and focus appearance. `TextInput` accepts `inputmode` (`text`, `decimal`, `numeric`, `search`, `email`, `url`, `tel`) for touch keyboard hints such as credit-limit amounts; it is a hint only and never replaces server-side or caller-side validation. `Field` renders its help and error with the id `${for}-message`, and `TextInput`, `TextareaInput` and `SelectInput` default `aria-describedby` to that id whenever they are given an `id`, so the association forms without the caller wiring it. Pass `ariaDescribedBy` explicitly to point elsewhere, and `ariaInvalid` when the field is in error. Do not document imaginary error or loading props.

`SearchSelect` is the shared single-value picker for long named resource lists. Its trigger preserves the chosen label while the popover filters by label and stable identifier, exposes combobox/listbox semantics, supports ArrowUp/ArrowDown/Enter/Escape, and returns focus to the trigger after keyboard selection or dismissal. Loading and no-match copy stay inside the control. The popover portals to `document.body` as a viewport-fixed shared-popover layer, chooses the roomier side of the trigger, and bounds its list height so Card/table overflow cannot clip long catalogs. It remains width-contained on mobile; do not replace it with a full-height native `<select>` for user, project, or other long catalogs.

Any long OpenStack resource catalog picked inside a stacked settings list — including every `/admin/settings` resource policy — MUST use `SearchSelect` rather than a route-local absolute dropdown: a dropdown pinned below its input is clipped by the page bottom, so results at the end of a long settings page cannot be read or clicked. `SearchSelect` places the popover on the roomier side of the trigger, so a picker near the viewport bottom opens upward and remains fully visible. Optional `onopen` lets a caller lazily fetch or retry its catalog when the popover opens; it never changes placement, filtering, or dismissal behavior.

Offer choices over typing. A field whose valid values are an enumerable OpenStack catalog — datastore, version, flavor, availability zone, volume type — uses `SelectInput` or `SearchSelect`, and falls back to free text only when the catalog failed to load and `Field help` says so. A placeholder may only illustrate the shape of an expected value; any constraint the user must keep satisfying while typing — minimum length, allowed characters, unit — also appears in `Field help`, because the placeholder is gone at the first keystroke. Validate while the user is still in the form: a detected problem appears in `Field`'s `error` slot ahead of `FormModal`'s `onSubmit`, not only as a post-submit `Alert` or `Toast`. `TextInput type="password"` and every other secret input starts empty, never binds a server-returned secret, and never renders a stored secret as its value; that a secret is already stored is stated with `Pill` or `Field help`. `/admin/settings` carries only the global, infrequently changed defaults that `AdminLoginBrandingPanel` and `AdminResourcePoliciesPanel` already hold; a per-route filter, sort, column, page-size, or view control stays in that route's `ResourceToolbar` or `ToggleGroup` where its effect is visible.

## Feedback/overlays/tables

Use `Alert`, `Toast`, and `EmptyState` for feedback; `StatusChip` + `getStatusStyle` and `Pill` for status; `TableShell` for tabular data. Modal is the scrim/dismissal shell and `Card surface="modal"` is the panel surface. Table density is normal `0.75rem × 1rem` or compact `0.5rem × 0.75rem`. UsageBar default thresholds are warning 80 and danger 95; it accepts `percent` or `value`/`max`, clamps invalid or out-of-range percentages to `0–100`, and for `max={-1}` labels the quota `무제한` without a percentage or fill. Use `UsageBar`, `QuotaBar`, or `CapacityBar` instead of route-specific bars.

`UsageBar` places its default full width and `min-width: 0` in the `components` cascade layer, so caller width utilities such as `w-14` remain authoritative. Inline meters reserve independent space for their text; administrator project-resource headers and rows share a 0.75rem column gap, and long numeric readouts wrap within their own cell rather than crossing the next column. Narrow screens retain the table's local horizontal scroll.

`UsageRing` is the compact inline counterpart to `UsageBar`: use it only where a quantitative meter must share a narrow control row, such as the chat composer. It uses the same threshold contract, remains a `role="meter"` with an explicit text equivalent, and never replaces the full UsageBar on settings, quota, or detail surfaces.

Feedback lives in the interface, not in an interrupting dialog. A data surface paints `frontend/src/lib/components/LoadingSkeleton.svelte` — which sits outside `ui/` and is referenced by path, not as a primitive — or its own `TableShell` header plus placeholder rows, from first render and shows `EmptyState` only after the request resolves with zero results, never while it is still pending. A failed session, catalog, or first-load request detected while mounting is reported with an inline `Alert` inside the route's `PageShell`, never by opening `ConfirmDialog` or `Modal` before the user has acted. Failure copy in `Alert` or `Toast` names the operation that failed and the step that resolves it, and exposes that step through `Alert`'s `actions` snippet or the toast `action.label` whenever a retry, settings, or navigation path exists, instead of a bare `오류가 발생했습니다` fallback.

`ConfirmDialog` is reserved for operations no surface can reverse. An action whose reversal is already reachable from the same controller with the arguments in hand — `setDeleteOnTermination(volumeId, !next)`, or `attachVolume` after `detachVolume` — proceeds without a dialog and reports through `toast` with a `ToastAction` that performs the reversal and an explicit `duration` longer than the 4000ms default. Because `ConfirmDialog` renders only `dialogState.message` above its hardcoded pair, that message is the only text that can predict the outcome: every caller names the specific resource and states that the operation cannot be reversed.

A modal holds one scoped task. `FormModal` keeps that task inside its `min(calc(100vw - 2rem), 28rem)` frame with no nested step hierarchy; multistep or browse-heavy work belongs in `SlidePanel` or its own route. A caller that overrides `FormModal`'s `actions` snippet still renders a non-confirming exit, because the override replaces the default cancel/submit pair entirely, and `Modal dismissible={false}` is permitted only while an action is in flight — the `dismissible={!submitting}` pattern — never as the resting state of an open dialog. A `SlidePanel`'s default `width` presents its primary content and controls without resizing, because the drag handle is gated behind `resizable && isDesktop` and the persisted `storageKey` width applies only at `md` and above; no required control may be reachable only by widening the panel.

볼륨 이전은 개별 available·미연결 볼륨의 생성 작업과 목록 상단의 **볼륨 수신 / 대기 중인 이전**을 독립 scoped task로 연다. 수신 프로젝트에 기존 볼륨이 없어도 두 목록 진입점은 유지한다. 기존 `Modal` + opaque `Card surface="modal"`, `Field`/`TextInput`, `Button`, `Alert`를 사용하고36rem·viewport margin 제한과 고정 header/footer·내부 body scroller를 유지한다. 모든 폭에서 검색 button/Enter와 출발 도메인·프로젝트 이름/전체 ID, 볼륨 ID·용량·유형, 대상 프로젝트를 표시하고 auth key는 조회 이후 password input으로 받는다. 긴 ID는 영역 안에서 감싸고 작은 화면에서 정보를 숨기지 않는다.

발급 화면은 ID/키 별도 복사와 manual recovery를 제공하며 source 새로고침으로 닫히지 않는다. ID 편집·사용자/프로젝트/토큰·쓰기 권한·rescope 시작·닫기·해제는 결과/키를 즉시 폐기하고 늦은 응답을 버린다. Busy 중 제출·일반 닫기를 막되 인증 scope 회수는 계속 적용한다. Native key·권한·상태 오류는 실제 사유를 보존하는 inline Alert로 표시하며403 전체를 잘못된 키라고 단정하지 않는다. 새 palette·token·motion·layer·primitive는 추가하지 않는다.

## Status & data visualization

Operational status uses exact, case-sensitive `getStatusStyle(status: string | null | undefined)` and its five tones; unknown or falsy status is neutral. Status conveys label plus tone and, where applicable, transition dot; color alone is never state. Charts use the six ordinal `CHART_COLORS`; topology preserves its domain colors. The topology canvas view alternates tenant zones between `--color-topology-internal` and `--color-topology-internal-2`, uses `--color-topology-gateway` only for L3 device stripes and glyphs (never as a status tone), and paints zone fills with `color-mix()` at `--topology-zone-fill-alpha` (`--topology-zone-fill-alpha-active` when selected) over the `--color-topology-grid-minor`/`--color-topology-grid-major` grid. A trunk badge renders only when it carries information no single switch card does — `trunkNetIds` of at least two, and at most one badge per router. That condition holds only for an external or shared provider-tier uplink, so the one caption that can ever render is `하위망 합산`, which names its scope in visible text: it sums only the tenant networks directly behind that router, never provider-wide totals. A lower tenant switch link is not badged at all; its switch card carries the number. A trunk over one network resolves to that network's own `traffic.networks[netId]`, which the adjacent switch card already prints, and the badge sits at the router↔switch midpoint, which is not required to fall inside its own zone; tenant trunks always carry exactly one network and are therefore never badged. Badges hide below `k < 0.5`, the same threshold at which node cards drop `.node-sub`, so no zoom level shows a badge beside cards that have been stripped of their own rates. Below that threshold the canvas carries no traffic figures; zone-label CIDR and admin pills are HUD and stay.

토폴로지 케이블 생성은 accent 색의 출력 포트와 가능한 입력 대상 테두리로만 affordance를 보인다. 포트는 카드 경계를 0.625rem 넘을 수 있어야 하므로 카드 컨테이너는 clipping하지 않고, NIC 목록만 내부 overflow를 자른다. 드래그 중 임시 케이블은 accent 점선과 endpoint dot을 사용하며 pointer event를 가로채지 않는다. 이 상태 표시는 선택/오류 status tone을 대체하지 않고 `Escape` 또는 무효 drop에서 즉시 사라진다.

Image catalogs share `ImageVerificationBadge` and existing Pill tones: success `검증됨`, warning `미검증`, neutral `검증 불가`. This is administrator approval, not malware scanning, ownership, or public visibility. Each tag has its own badge; repository cards show separate totals across every tag rather than presenting one verified tag as approval of the whole repository. Shared filters use one column on mobile, two on tablet, four only at xl. Repository cards use one column on mobile and two at md; user catalogs expand to three at lg, admin catalogs at xl. Admin tag management uses equivalent one/two-column cards below lg and a compact TableShell at lg; desktop tag labels remain separate from truncated repository names. VM 생성 이미지 선택은 repository 이름을 먼저 고르고 해당 이름의 current 태그를 선택하는 두 단계다. 클릭한 이름 카드는 그 자리에서 한 개만 펼쳐지며, 헤더 바로 아래에 해당 repository의 태그 이름 검색과 `TableShell` 단일 행 목록을 둔다. 검색은 앞뒤 공백을 제거한 대소문자 무시 부분 일치이며 다른 repository를 열면 초기화한다. 각 행의 열은 **태그 이름 · 해시값 · 업로드 시각 · 용량** 순서이고 좁은 화면도 두 열 카드로 바꾸지 않고 목록 안에서만 가로 스크롤한다. SHA-256/512는 짧게 표시하되 전체 값을 title·접근성 이름으로 보존하고, 업로드 시각은 `created_at`을 현재 언어의 날짜·초 단위 시각으로 표시한다. 미확인 날짜·크기는 `-`다. Repository 요약에는 SHA·raw·active/현재 Pill을 노출하지 않으며 UUID는 일반 선택 행에서 숨긴다. 이름과 태그 모두 최신 업로드가 먼저이고 날짜가 없는 항목은 뒤에 둔다. inactive current 태그는 선택 불가 사유와 함께 비활성화하며 과거 active UUID로 대체하지 않는다. 검색·접기·카드 전환은 선택 UUID를 바꾸지 않고 헤더에 선택한 태그를 유지한다. 과거/누락 UUID의 보존 경고와 기존 catalog의 SHA·UUID 상세 표시는 유지한다.

VM chooser의 compact digest는 알고리즘 이름·말줄임 suffix 없이 SHA 값의 **앞 8자리**만 보이고 전체 알고리즘·값은 title·aria-label로 남긴다. 메타데이터 열은 해시 4.5rem·업로드 시각 9rem·용량 4rem, 열 간격은 0.5rem이며 나머지는 최소 18rem의 태그 이름 열이 사용한다. 목록 최소 39rem과 기존 `TableShell` 지역 가로 스크롤을 유지한다. 잘린 태그의 전체 이름은 이름 셀 전체에 native title로 제공하며 inactive 행의 사유 title을 덮어쓰지 않는다. 좁은 해시 열에서 pending/unavailable 문구가 잘려도 전체 문구의 title을 남긴다. 공용 `ImageDigest`의 기본 catalog SHA·UUID 표현은 바꾸지 않는다.

VM create flavor choices keep fixed catalog specifications and separate target-project quota from one-host CPU/RAM/GPU capacity; only the VM wizard requests capacity, so K3s/Drover flavor pickers keep quota-only labels. `생성 가능` and `생성 불가` views retain named quota shortages, same-host shortages, and `확인 불가`; a global free-GPU count never authorizes a row.

사용자·관리자 VM 생성의 표시 순서는 **Flavor → 이미지/기존 볼륨 → 설정 → 검토**다. 내부 raw step ID는 2→1→5→6을 유지하고 진행 방향은 표시 index로 정한다. 이미지 추천은 기존 Alert/Pill과 repository/tag 선택을 재사용하며 current active·관리자 검증·명시적 GPU vendor/driver metadata가 추천 근거다. CPU의 GPU 이미지 오버헤드와 GPU 호환성 미보장·메타데이터 부재를 구별한다. 추천이나 Flavor 변경은 사용자의 이미지 UUID를 자동으로 바꾸지 않는다.

새 이미지 부트 볼륨 용량과 자동 보호 fieldset은 넓은 패널의 인접 두 열, 좁은 패널의 한 열이다. 독립 스냅샷·백업 checkbox는 기본 꺼짐·44px label이며 예약/보존/추가 storage quota를 표시한다. 하나라도 켜면 기존 warning Alert와 기본 미선택의 반복 force 동의를 노출하고 다음/검토/직접 제출에서 동의 여부를 확인한다. 기존 볼륨은 정책을 덮어쓰지 않으며 검토에는 두 정책 상태를 별도로 표시한다. 검토 사양은 좁은 폭에서 한 열로 풀고 이름·GPU alias를 내부 줄바꿈하며 지역 스크롤·기존 token/primitive를 유지한다.

VM 쿼터 preview는 기존 할당량(accent)·이번 VM 추가량(action-warm, 한도 초과 시 danger)·미사용 영역(surface-sunken)을 별도 범례와 현재→생성 후 수치로 표시한다. VM·vCPU·RAM뿐 아니라 새 부트 볼륨의 선택 크기를 DISK 추가량으로 반영하며 기존 볼륨 재사용은 0GB 추가다. 긴 수치는 셀 내부에서 줄바꿈하고 같은 행의 meter는 아래쪽에 맞춘다. 검증된 최근 GitHub ID를 동일 normalized login으로 재선택하면 canonical 프로필과 진행 가능 상태를 유지한다. 인스턴스 기본 정보의 GitHub SSH 값은 명시적 mode·login이 있을 때만 `@login`으로 표시하며 긴 ID는 셀 안에서 줄바꿈한다.

## Motion

`MOTION_CSS_VAR`, `MOTION_DURATION_MS`, and `REDUCED_MOTION_QUERY` are the shared vocabulary. Fast `--motion-duration-fast: 120ms` + `--motion-ease-standard: ease` is hover/focus/color feedback. Base `--motion-duration-base: 160ms` is control movement, compact fills, and fades. Panel `--motion-duration-panel: 200ms` + `--motion-ease-out: ease-out` is drawer/fly/pop. Data `--motion-duration-data: 500ms` is long-form resource/build progress. Status pulse `--motion-duration-status-pulse: 1400ms` + `--motion-ease-in-out: ease-in-out` is status dots.

Spin `--motion-duration-spin: 800ms` is rotation loops (spinner rings, orbit tracks). Shimmer `--motion-duration-shimmer: 1600ms` is sweeps, travelling packets, indeterminate bars, and connector flow. Stagger `--motion-duration-stagger: 40ms` spaces a cascade and stops growing after `MOTION_STAGGER_LIMIT` (8) items. `--motion-ease-emphasized: cubic-bezier(0.2, 0, 0, 1)` is entrances, fills, and draw-ins; `--motion-ease-overshoot: cubic-bezier(0.34, 1.56, 0.64, 1)` is the pop of an appearing mark or surface. `--motion-sheen` is the highlight swept across an in-flight fill. `--motion-skeleton-highlight` is the band swept across a skeleton block; it is themed (faint white on dark, where the sunken placeholder is lighter than raised surfaces, strong white on light). `MOTION_EASING` mirrors the two curves for Web Animations, which cannot read CSS variables.

Animate opacity, translate, or scale only; never animate layout dimensions. Hover is decoration, never the only status signal. Repeating animation is limited to loading, progress, and status. `prefersReducedMotion()` and `motionDuration()` make JavaScript transitions immediate. The global reduced-motion contract sets every motion duration variable to `0.01ms` (stagger to `0ms`) plus Tailwind `--default-transition-duration` and `--default-animation-duration`, scroll to `auto`, and universally overrides animation/transition duration and delay.

VM 배포 시간은 motion이나 SSE 도착 간격이 아니라 store가 관측한 monotonic clock이다. 총 경과 시간과 실제 시작된 단계의 경과 시간을 1초 단위로 계속 표시하고, 완료한 단계는 관측 소요 시간을 고정한다. 중복 stage와 오래된 server elapsed는 시계를 초기화하지 않는다. 완료·실패·stream 종료·destroy에서 멈추고 retry는 새 시계를 시작한다. 실패/완료하지 않은 단계를 추정해 만들거나 percent를 시간에 따라 증가시키지 않는다. 성공은 사용자 `/dashboard/compute/instances` 또는 관리자 `/admin/instances` 목록으로 이동한다.

SVG strokes are the one paint exception to transform-only motion: `stroke-dashoffset` may animate (never path geometry) for a one-shot `.motion-draw` against `pathLength="1"` and for `.motion-flow` dash marching on a connector that represents live work or measured traffic. A stroke with its own dash pattern uses `.motion-fade` instead.

`layout.css` owns the shared `motion-*` keyframes and utilities: `.motion-enter`, `.motion-fade`, and `.motion-pop` mount entrances (a manual cascade sets `--motion-index`; `--motion-enter-offset` and `--motion-enter-x` set where `.motion-enter` starts, so a side drawer such as `SlidePanel` enters from its edge); `.motion-stagger` (children cascade, capped at eight); `.motion-draw`; `.motion-flow`; `.motion-spin`; and `.motion-skeleton`, the shimmer placeholder block that replaces `animate-pulse` placeholders. Entrances fill `backwards`, so no transform or opacity remains once they end and fixed descendants regain the viewport containing block. Loops rest on their base style, which must be the meaningful static frame because reduced motion runs every animation once for `0.01ms`: hidden packets and sheens, a full static spinner ring, resting bars. Mount entrances are CSS classes rather than Svelte transitions, so they cost no script and stay inert under jsdom. Svelte transitions are reserved for keyed swaps and exits and use `enter`, `pop`, `fadeMotion`, and `reflow` from `frontend/src/lib/utils/motion.ts`, which become immediate when reduced motion is requested or `Element.animate` is unavailable; a transition that must play when an enclosing conditional mounts (a toast region's first item) is marked `|global`. Dialogs and focus-trapped overlays enter only — they never hold an exit transition that would delay focus restoration or keep the page `inert`. Components do not redeclare spin, blink, pulse, or indeterminate keyframes.

Motion primitives carry real state only. `ProgressTrack` is determinate (`value` clamped to `0–100`) or indeterminate (`null`, never a fake value); its fill scales from the left, grows in on mount, and `active` sweeps the sheen while work is in flight. `StepProgress` lists operation steps: done (drawn check), active (spinning arc, ripple, a packet travelling toward the next step, visible `진행 중`), pending (dashed outline and number), and failed (drawn X, visible `실패`); an unknown current id means not started, never a guessed step. `ProvisionPipeline` draws the same state model as icon stations joined by conduits that fill behind finished stations and flow into the active one; beside a `StepProgress` listing the same stages it is `decorative`, and below `md` its labels collapse to screen-reader names. `ActivityIndicator` variants carry meaning — spinner for work, dots for waiting on a reply, orbit for a model thinking, bars for audio or stream output, pulse for live status, upload/download for transfer direction — and the glyph is always paired with visible text, its own `label` or adjacent copy. `AnimatedNumber` counts toward a value only where it is laid out and motion is allowed, hides intermediate digits from assistive technology, and settles on the exact value text.

Console shells fade route content in with `playRouteEntrance` after a client navigation that changes the path (`isRouteChange`); hydration and query-only updates do not animate. The fade is opacity-only so a deep-linked fixed panel keeps the viewport containing block.

A new duration or easing curve is defined in `layout.css`, exposed through `MOTION_CSS_VAR`/`MOTION_DURATION_MS`, and given its `designSystemRules` test entry before any feature uses it. Motion the CSS contract cannot reach — `Element.animate()`, `requestAnimationFrame` loops, and any explicit `scrollIntoView`/`scrollTo` with `behavior: 'smooth'` — branches on `prefersReducedMotion()` at the call site, because the reduced-motion block overrides only CSS `animation-*`/`transition-*` and its `scroll-behavior: auto` loses to an explicit `behavior` argument; the ChatPanel composer nudge, the notifications announcement focus scroll, and the topology canvas camera tween are the compliant pattern. An overlay stays cancellable while its own transition runs: `SlidePanel` and `ProjectQuotaPanel` fire `onClose` immediately from the scrim and the close control rather than deferring to a transition-end event or timer, and no control is disabled because an entrance or exit transition is running — disabling for in-flight work such as an active save is unrelated and remains allowed.

Named motion exceptions: `--landing-ease`; ChatPanel composer `cubic-bezier(0.22, 1, 0.36, 1)`; library-contained Bklit plot transitions (disabled by its host under reduced motion); 600ms landing reveal; 7-second tutorial hint; `0.8–1.2s` linear loading loops; and 토폴로지 캔버스 패킷 흐름 시뮬레이션 (기본 on, 툴바 토글로 끌 수 있음, prefers-reduced-motion 시 완전 비활성, rAF 기반 transform 이동). Do not copy exceptions into ordinary components.

Public kinetic artwork may use the shared `motion-assemble` keyframe: an opaque composite object translates and gently rotates into its final mechanical arrangement. `--motion-assemble-x/y/angle` describe displacement, not a second duration/easing system; data/stagger tokens own timing. This finite editorial rotation exception never applies to controls or body text. Only moving pieces without attached external wires may assemble; a route appears after its endpoint pieces settle. Never independently fade solid faces, animate path geometry, or imply live work. Complete text and artwork are the base frame; hidden/offscreen pauses, replay, reduced-motion and no-JS follow the landing controller contract.

## Accessibility

Never communicate status, selection, loading, or disabled state through color or animation alone: pair visible text and the relevant attribute/reason. Maintain visible keyboard focus with `--focus-ring`. Every `role="dialog"` surface reaches the `dialogFocus` action (`frontend/src/lib/utils/dialogFocus.ts`), which is now the single implementation of dismissal and focus containment: it moves focus into the dialog on open, marks every ancestor-branch sibling `inert` so `aria-modal="true"` is a true claim, closes the top layer only on Escape, and restores focus to the opener. A dismissal handler declared on the overlay element itself is the anti-pattern this replaced — focus never entered those overlays, so the handler could not fire and the modal boundary sealed assistive technology out of a surface it could not leave. A new floating surface wires `use:dialogFocus` rather than its own `onkeydown`, and passes the open expression as `enabled` when the element is not already inside an `{#if}`.

Normal-sized public/editorial labels use `--color-ink-2`, `--color-warm-text`, or `--color-state-success-text` so both themes retain WCAG AA contrast without changing the dark brand palette. Reserve `--color-ink-3` for disabled text and raw `--color-warm` / state tones for large display text or non-text decoration.

Type is declared in `rem` rather than arbitrary `text-[Npx]` values, and every new or materially changed surface is verified at 200% browser zoom with `PageShell` hierarchy intact, `TableShell` headers readable, and every action still reachable; the absolute `body { font-size: 14px }` in `layout.css` and the `Sidebar`, `AdminSidebar` and `CmdPalette` islands are pre-existing usages that new work does not extend. Console type below the `0.75rem` floor was swept out of the rest of the application: no surface outside those three islands declares 8, 9, 10, 11 or 12 pixels any more. What remains off-ladder and is deliberately left alone is `text-[13px]`, which renders at the `0.8125rem` row tier and has no Tailwind step to convert to without inventing a spelling, and the `text-[15px]`/`text-[26px]`/`text-[28px]` display sizes, which sit above the ladder's `1.25rem` top and need a documented display token rather than a swap. A row, card, or code surface must not reveal a control by pointer hover alone: an action behind `group-hover` also appears on keyboard focus with `--focus-ring` visible, or stays permanently visible the way `ActionMenu` keeps its trigger — `ObjectFlatTable`, `ObjectTreeTable`, and `K3sYamlView` are existing debt, not the pattern to copy. A chart, meter, or multi-series surface carries series identity and magnitude in an encoding a colorblind reader perceives without distinguishing hues — an adjacent label and value the way `QuotaDonut` renders its `label`, or a distinct shape or pattern per series — and a screen-reader equivalent never substitutes for that visible encoding.
