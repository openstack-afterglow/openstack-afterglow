# Afterglow Design System

## Product character & authority

Afterglow is a dark-first cloud operations console: neutral graphite surfaces support dense operational work, warm orange identifies the single highest-priority affirmative action, and blue/purple remain reserved for data and semantic information. Light mode remaps the same semantic hierarchy; it is not a separate brand.

New UI follows this authority order: `frontend/src/routes/layout.css` owns theme and runtime CSS values; `frontend/src/lib/design/tokens.ts` exposes TypeScript metadata; `frontend/src/lib/components/ui` owns reusable behavior and markup; feature routes and components compose those primitives. `:root.light` legacy palette overrides are a compatibility boundary for existing visual debt, never a new API.

Branding defers to content. Inside the authenticated console the brand mark occupies exactly one slot per rendered surface — `RingMark` in the `Sidebar`/`AdminSidebar` header row — and no route spends `PageShell` width or height on an element whose only job is brand display; `--warm-grad` exists to paint that mark and buys no content area. Unauthenticated entry routes instead carry `LoginBrandHeader`'s configured site logo and the public landing surface keeps its own navigation and footer brand contract; administrative branding previews (`AdminLoginBrandingPanel`) and third-party provider marks are outside this rule.

## Apple HIG adoption and non-goals

Afterglow borrows Apple's interaction behaviour, not Apple's visual system. The reference is the local Human Interface Guidelines copy in the `apple-design` skill (`~/.claude/skills/apple-design/references/hig/`); cite a rule as `file.md › Heading` when a review turns on it. A web application takes Apple's principles and foundations — accessibility, layout, typography, writing — plus the desktop conventions lens of pointer, keyboard, and multi-pane hierarchy; it does not take the iOS touch-platform conventions.

Apple's eight principles are the first review filter, and a surface that breaks one has a larger problem than any single rule it breaks: purpose, agency, responsibility, familiarity, flexibility, simplicity, craft, delight. Afterglow is a dense operations console, so ties break toward simplicity and familiarity. Every conclusion is a review finding naming the `frontend/src/lib/components/ui` primitive or the rule in this document at fault; a contrast or hierarchy complaint stays a finding and never authorizes changing an existing `--color-*` value in `layout.css`.

Afterglow's own characteristics and items sit outside the adoption entirely. The persistent sidebar hierarchy and its responsive drawer, the `:root.light` remap, the Pretendard/IBM Plex Korean stack, the warm `Button variant="primary"` CTA, `getStatusStyle`'s five operational tones, `UsageBar`/`QuotaBar`/`CapacityBar`/`UsageRing`, the topology canvas and its domain colors, the Palimpsest layer surfaces, and `ChatBubble` are the product's own vocabulary: follow Apple where the pattern is generic, and leave these as they are rather than restyling them to resemble an Apple component.

These parts of the HIG are deliberately not adopted, and no rule in this document may be read as authorization for them.

| Not adopted | Reason |
| --- | --- |
| Apple palettes, system colors, and contrast-driven changes to existing token values | The dark-first graphite and warm-orange system above is the product's identity and is to be preserved, warm `primary` emphasis included. A contrast shortfall is a finding against this document. Adding a new token still follows the New UI entity workflow. |
| Liquid Glass or any material inside the content layer | `materials.md › Liquid Glass`: "Don't use Liquid Glass in the content layer." `Card`, `TableShell`, `StatTile`, and form surfaces stay `1px solid var(--color-line)` with no shadow; only modal/popover elevation carries a restrained shadow. |
| `dark-mode.md`'s "no app-specific appearance switch" | Afterglow ships the `:root.light` remap and keeps it. |
| SF Pro, SF Compact, New York, and SF Symbols as families | Typography is locally hosted Pretendard and IBM Plex with no runtime font CDN. The principle that survives is one icon system whose weight matches adjacent text. |
| Title-style capitalization for buttons, menu items, and titles | The console is Korean. |
| Tab bars as top-level navigation | Top-level navigation is the persistent 15rem sidebar and its documented responsive drawer. |

Materials are admitted on one layer only, and membership is decided by one test: **does content actually pass beneath the surface?** A blur that samples a flat canvas or an interposed scrim produces no depth cue and only costs a compositing layer. Apple confines Liquid Glass to "a distinct functional layer for controls and navigation elements ... that floats above the content layer" and directs you to "use Liquid Glass effects sparingly" (`materials.md › Liquid Glass`), so the adopted set is deliberately short.

`--material-chrome-alpha` (`90%` dark, `85%` light) with `--material-chrome-blur` `1.125rem` belongs to the application header alone, which is `fixed` at `top: 0` while the main scroller starts at the same origin, so page content genuinely scrolls under it. The header carries it on an `inset-0` child at negative z-index rather than on the `<header>` itself, because a non-`none` `backdrop-filter` makes an element a containing block and would trap the header's own popovers. `--material-overlay-alpha` (`94%` dark, `90%` light) with `--material-scrim-blur` `0.75rem` belongs to `BulkSelectionOverlay`, the one control-layer surface with rows streaming beneath it. `--material-scrim-blur` alone belongs to the full-viewport scrims of `Modal`, `CmdPalette`, `ConfirmDialog`, and the admin evacuate/recovery dialogs, replacing four ad-hoc radii. `MATERIAL_CSS_VAR` exposes all four names. The alphas are set so the header stays readable at its worst composite — a dark glyph scrolling directly beneath it — which measures `#d6d7d9` in light (`--color-ink-0` 12.18:1, `--color-ink-1` 8.50:1, `--color-ink-2` 4.73:1) and `#2b2c2e` in dark (16.47 / 12.47 / 6.60 over canvas, 12.72 / 9.62 / 5.09 under a glyph). Light is the binding case and `--color-ink-2` is the binding token, so a light alpha below 85% or a darker `--color-ink-2` would drop header copy under AA; re-measure both whenever the light ramp moves.

These surfaces are excluded on evidence, not oversight. The sidebar is `position: sticky` at `md` and above with the main scroller beginning exactly at its right edge, so nothing passes beneath it; its sub-`md` drawer sits above a scrim that has already flattened the backdrop. A panel behind a scrim samples the scrim, never the content, so `Modal`, `SlidePanel`, and `CmdPalette` keep opaque panels and blur only the scrim. `ActionMenu` is excluded until its items stop deriving hover from opaque `--color-surface-sunken`: over a translucent panel that fill can land darker than the surface and the hover cue inverts.

The opaque background is the base declaration and translucency is the enhancement, so an unsupported browser, `prefers-reduced-transparency`, and `forced-colors` all fail safe to a solid surface. Those three blocks carry equal specificity, so source order is the contract — the accommodations must follow the `@supports` block or they are silently overridden — and `designSystemRules` pins that order. `Card`, `TableShell`, `StatTile`, and form surfaces stay opaque always. A material carries depth, never state.

The light ramp is derived from the dark theme, not from a framework's default scale — but the axis it borrows is chroma, not hue. Measured in OKLCH, the previous light neutrals already sat in dark's own hue band (light `#0f172a`/`#475569` at H 258-266, dark `#101113`/`#999ca5` at H 264-271); what made them read as a stock slate template was carrying 2.4-6.9x dark's chroma at that hue (`--color-ink-0` C=0.0398 against dark's 0.0013). The ramp now holds H 262-286 and cuts chroma to dark's envelope (C 0.0013-0.0154), so the reduction falls almost entirely on the ink, where it was tinting body copy blue, and barely touches the surfaces, which were already near-neutral. A warm ramp was tried first and rejected on sight as sallow: at L above 0.95 a near-zero chroma leaves hue under-determined at 8-bit, so "almost neutral" drifts to whatever rounding produces, and it landed at H 68-91. The surfaces therefore carry a deliberate chroma floor (0.0013-0.0055) in the cool direction rather than aiming at zero. Warm is unchanged in both themes: it is the identity anchor, and a palette revision is not licence to move it. Every chromatic token keeps full strength (C 0.076-0.200), so the neutrals losing their cast makes the orange read hotter, not the console flatter.

The light surface tiers are now distinct — `canvas` `#f2f3f6` -> `base` `#f7f8fa` -> `raised` `#fefeff`, OKLCH lightness steps of 0.015 and 0.018 — where they previously collapsed to 1.03:1 and 1.00:1 and left depth to hairlines alone. `--color-line-2` moved from `#cbd5e1` to `#7c8089` (3.72:1 on `base`, 3.57:1 on `canvas`, 3.44:1 on `sunken`), and the light `input`/`textarea`/`select` override, which had pinned those controls to `#ffffff` on a `#cbd5e1` border at 1.48:1, now reads the tokens — that override, not the token, was where SC 1.4.11 actually failed. Every neutral entry in the light legacy-override block is a `var(--color-*)` reference rather than a literal, so the ramp is the single source of truth and the two halves of the theme cannot drift to opposite temperatures again.

Warm has two tokens because one cannot do both jobs: `--color-action-warm` is the fill and border, where `--color-action-on-warm` sits on it at 4.94:1, and `--color-warm-text` is the copy, which reaches 4.87:1 on a light surface where the fill value gives only 3.35:1. Never paint text with `--color-action-warm`. Every semantic tone follows the same split. An action colour must be declared inside `@theme static`, not `:root`: Tailwind generates a utility only from a `--color-*` name declared there, and a name declared elsewhere silently produces no rule at all.

`--color-ink-3` is disabled text and nothing else, and the application now holds to that: the only remaining uses are the `disabled:` variant and `::placeholder`/`:disabled` rules in scoped CSS. It measures 4.42:1 on the light base and 3.29:1 on the dark base, so any content painted with it fails SC 1.4.3 — that is why the rule is absolute rather than a preference. A section label, a username, an empty-state sentence, a record count, a meter's own readout and a placeholder are all information, and all take `--color-ink-2`.

Use `SURFACE_CSS_VAR` rather than spelling surface variables in TypeScript-driven styles. Selection uses `SURFACE_CSS_VAR.selected`, never a filled blue/purple navigation treatment. Modal/dialog shells use `bg-surface-scrim`; drawers and sidebars use `bg-surface-scrim-soft`. `ConfirmDialog` intentionally keeps its canvas wash (`color-mix(in oklab, var(--color-surface-canvas) 72%, transparent)`) because it is not a black scrim.

Map legacy colors by role: gray/slate becomes surface, ink, or line; blue/purple become data or semantic information; green becomes success; red becomes danger; yellow/amber becomes warning; orange becomes warm. Small orange copy in light mode uses `--color-warm-text`, not raw warm. Do not collapse rose, indigo, cyan, sky, or teal into a generic tone: introduce a semantic token and primitive first when required. `CHART_COLORS`, topology external/shared/internal/internal-2/router/link/gateway colors plus the canvas zone-fill alpha (`--topology-zone-fill-alpha`, `--topology-zone-fill-alpha-active`) and grid tokens (`--color-topology-grid-minor`, `--color-topology-grid-major`), and GitLab `#FC6D26`/`#E24329` are domain or third-party-brand exceptions only.

### Type, spacing, geometry, and elevation

Typography has three explicit roles and no feature may redeclare a Korean-only font family. `--font-sans` is locally hosted Pretendard Variable for Korean body copy, controls, tables, and dense console UI. `--font-display` is locally hosted IBM Plex Sans KR for public-page hero, section, and editorial headings only; do not use it for ordinary console page titles or controls. `--font-mono` is locally hosted IBM Plex Mono followed by Pretendard, so identifiers and code remain technical without making ordinary timestamps or status copy harder to scan. All bundled fonts use WOFF2 and `font-display: swap`; do not add a runtime font CDN dependency.

Console body/form copy is `0.875rem`/400. Resource rows, navigation, and buttons are `0.8125rem`/500. Support labels, status, and metadata are at least `0.75rem`; only identifiers and code use mono. Page titles are `1.25rem`/600 with `1.75rem` line-height. Breadcrumbs are ordinary-case `0.75rem` muted text with tight tracking. Quotas, metrics, and timestamps use tabular figures. Body copy keeps a relaxed line-height; dense labels use 500 or 600 rather than synthetic bold. Update this document before adding another type size or role.

`PageShell` max widths remain `none`, `5xl`, and `7xl`; route padding is `1rem` mobile and `1.5rem` tablet/desktop (`0.75rem`/`1rem` dense). The spacing rhythm is 4px. Radius is token-backed. `--radius-sm` `0.25rem` and `--radius-md` `0.375rem` are the control tier, `--radius-lg` `0.625rem` is ordinary panels, cards, and tables, `--radius-xl` `0.875rem` is dialogs, and a literal `999px` capsule stays reserved for status pills, avatars, and meters. These four override the Tailwind scale that `rounded-sm`/`rounded-md`/`rounded-lg`/`rounded-xl` resolve against, so geometry retunes in `layout.css` instead of across feature files, and `RADIUS_CSS_VAR` exposes the same names to TypeScript. Tier by rendered size, not by role name: a control under roughly 32px takes `--radius-md`, because at the panel radius a 26px row-action button reads as a capsule and stops being separable from a `StatusChip`. Ordinary surfaces use `1px solid var(--color-line)` with no shadow; required interactive boundaries use `--color-line-2`. Only the floating layer carries elevation, through three tokens exposed as `ELEVATION_CSS_VAR`: `--shadow-restraint` for unanchored dialogs and panels, `--shadow-popover` for a surface anchored to the trigger it must stay attached to, and `--shadow-overlay-compact` for an unanchored surface under `20rem` wide, where the deep ambient layer overshoots the element casting it. Each is defined in `:root` with its own `:root.light` alpha, because a dark shadow reused on white reads as grime rather than depth. A `var()` naming an undefined token computes `box-shadow: none`, so an elevation token is never referenced before it is defined. Primary actions are flat warm fills without gradient or glow. Focus is `--focus-ring = 0 0 0 2px var(--color-surface-base), 0 0 0 4px var(--color-line-2)`; removing an outline is allowed only when the same visible ring replaces it, with a native outline fallback in forced-colors mode.

### Layering and focus

`LAYOUT_CSS_VAR` exposes `--app-header-height: 3rem` and `--app-sidebar-width: 15rem`. `LAYER_CSS_VAR` exposes the runtime order: `--z-sidebar` 30; `--z-header` 35; `--z-panel` 40; `--z-modal` 50; `--z-toast` 60; `--z-confirmation` 200; `--z-popover` 210; `--z-command` 220. Sidebar/AdminSidebar use sidebar; the root context bar uses header; desktop SlidePanel uses panel; mobile SlidePanel and Modal use modal; Toast and BulkSelectionOverlay use toast; ConfirmDialog uses confirmation; ActionMenu uses popover; CmdPalette uses command with its panel at `calc(var(--z-command) + 1)`. In a shared stacking context, backdrop precedes panel in DOM order. Feature composition must not create page-level stacking contexts that trap overlays below the shell.

### Gradients and chrome

`--gradient-brand` remains logo/brand/editorial decoration. `Button variant="primary"` is a flat warm fill and the single highest-priority affirmative CTA per task surface. `--gradient-usage`, `--gradient-usage-warning`, and `--gradient-usage-danger` remain quantitative bars only. `--warm-soft`/ring and `--accent-soft`/ring are semantic tints; `--admin-tone*` belongs only to admin context. Reuse global scrollbar tokens; do not add component-scoped scrollbar styling.

## Layout & responsive hierarchy

Use the existing Tailwind breakpoints only: mobile is `<768px`; tablet is `md` (`768–1023px`); desktop is `lg` (`≥1024px`). `sm` (`≥640px`) is a compact mobile refinement, not a separate layout tier; use `xl` only to increase density after the desktop hierarchy already works. Do not introduce a component-specific breakpoint without updating this section and its test.

**Mobile (<768px).** `PageShell` route/dense padding is `1rem`/`0.75rem`. Navigation opens as the hamburger-controlled, dismissible sidebar drawer; project selection and mode switching remain explicit in the drawer. Header utility actions use 44px touch targets. Start resource and form layouts as one column; a two-column compact statistic group is allowed when each value remains readable. Header actions wrap or stack rather than clip, and the highest-priority action remains visible without hover. `TableShell` stays horizontally scrollable with headers intact; do not silently transform a table into cards unless the route provides and tests an equivalent semantic card view. SlidePanel is full-viewport and modal with a visible close path.

**Tablet (768–1023px).** `PageShell` route/dense padding becomes `1.5rem`/`1rem`. The 15rem sidebar is persistent, PageHeader remains stacked and its actions wrap; sidebar search remains the compact search entry point. Use two columns for comparable cards/forms where each control has usable inline space. Desktop/tablet SlidePanel is non-modal so header/sidebar navigation stays usable.

**Desktop (≥1024px).** Keep the same PageShell padding and persistent sidebar. PageHeader becomes inline and actions still wrap when labels would clip. The header exposes its desktop search and project/context controls. Three-or-more columns are allowed only when the minimum card/control width and scanning order remain clear; use PageShell max widths instead of stretching sparse content.

At every width, group by relationship rather than by leftover space: unrelated controls take their own `Card` group, optionally labeled by `SectionHeader`, instead of one shared control row, so adjacency always means the actions are related. Sibling `Card` and `StatTile` groups in a multi-column layout share one grid definition so labels, values, and control edges align across the row instead of each cell being hand-sized to absorb `PageShell` width. A `TableShell` cell holds one short scannable value; long-form or secondary detail moves to the row's detail route or the shared `SlidePanel`, never into a wider or wrapping cell.

Mode controls always label and icon the current route surface (`사용자 모드` or `관리자 모드`); their link destination, title, and accessible name describe switching to the opposite surface. Mobile and tablet place this control in the sidebar, while desktop places it in the header. The 1024px handoff must expose exactly one visible control with identical state semantics.

Sidebar group activation and automatic expansion follow the group's declared item routes (exact path or slash-delimited descendants), not a shared URL namespace. Topology is a standalone item even though its URL remains `/dashboard/network/topology`; entering it must not activate or expand Network, nor reset manually opened or collapsed groups.

Sidebar and AdminSidebar carry at most two navigation levels — a group header and its item list — in both the `sections` arrays and the hardcoded group markup; deeper resource hierarchy belongs to the route's own `TableShell` or detail route. Every new or materially changed sidebar destination is also registered in `frontend/src/lib/config/nav.ts` so `CmdPalette` resolves it from the one ⌘K location; `nav.ts` is the palette index only and the sidebars keep their own route data. `CmdPalette` names the scope its index was built from — at minimum the active project and the 사용자/관리자 mode — in its own placeholder or panel header, because its full-viewport `aria-modal` scrim covers the sidebar mode control and header `ProjectSelector` that otherwise carry that context.

Console shells use `100dvh`, one main workspace scroll owner, the shared geometry variables, and one focusable `main#main-content` landmark per rendered surface. Test every new or materially changed visual flow at mobile, tablet, desktop, 767/768, and 1023/1024 cutovers. Confirm navigation, action placement, overlay sizing/dismissal, readable resource selection, and table overflow/card fallback. Preserve information and interaction parity across widths; a smaller viewport may change composition, never silently remove required state or a reachable action.

Authentication verification outages use the existing non-dismissible `Modal`, `Card surface="modal"` and `Button` primitives, not disappearing toasts or normal-refresh dimming. The recovery surface is bounded to `min(28rem, 100vw - 2rem)` at every breakpoint and sits above existing command/confirmation overlays at `calc(var(--z-command) + 2)`. `dialogFocus` makes the underlying mounted workspace inert so drafts survive but normal operations cannot continue as though authentication succeeded. It offers explicit logout and a cooldown-aware primary retry; action rows wrap on mobile. The non-dismissible backdrop is disabled/hidden to assistive technology, so initial focus lands on an actionable control. Terminal invalid authentication instead clears the session and navigates to login.

### Global Cloud Shell

Cloud Shell is global console chrome, not route content. Its header trigger appears after the breadcrumb/admin context actions and before the theme toggle whenever the authenticated site capability is enabled. The trigger never provisions on open: `CloudShellAuthorizeDialog` first names the current project authority, short-lived tmpfs credential, persistent 5GiB-per-project home, idle/max termination, and approval required for every new session. Cancel performs no API call; approve is the single warm primary action.

The connected surface is a fixed bottom dock that persists across ordinary route navigation. Mobile `<768px` is a bottom sheet capped at `88dvh` with 44px header controls and no horizontal overflow. Tablet `768–1023px` begins at `--app-sidebar-width`, defaults to `45dvh`, and supports pointer plus Arrow/Home/End height adjustment up to `70dvh`. Desktop `≥1024px` uses the same sidebar offset and a 360px default. Minimize retains identity/status in one header row; maximize uses the allowed viewport while keeping application header/sidebar navigation reachable. The dock uses `--z-panel`; consent/reset confirmation use existing modal/confirmation layers.

Terminal focus is user work. Escape does not close or minimize the dock while xterm is focused; termination requires the visible close button. Project switch and logout close the terminal before auth scope changes. Close destroys the ephemeral session but preserves home. Home reset stays in the overflow menu, uses `ConfirmDialog`, refuses an active session with an inline warning, and shows success only after the DELETE response.

Every state uses `StatusChip` + `getStatusStyle`: preparing/provisioning/authorizing/ending are warning, ready is success, closed is neutral, and error is danger. Progress and actionable error copy remain visible beside the terminal; color and animation never carry state alone. No Cloud Shell-specific palette or motion token exists.

`terminalTheme.ts` maps xterm's background/foreground/cursor/selection/ANSI colors to existing CSS tokens and reapplies them when the resolved light/dark theme changes. Global Cloud Shell, Zun container terminal, and k3s shell overlay share that mapping and xterm CSS import. Raw hex themes and component-local terminal palettes are prohibited. Resizing calls FitAddon and sends bounded JSON dimensions; terminal bytes remain binary and are never treated as display text by the controller.

Chat exposes 44px history/settings and source-list controls in the workspace header at every width, including a visible empty-source state. Mobile places model/agent selection and history/source actions on separate rows; tablet and desktop keep one row while space permits. Below 1024px the history/user footer is a bounded overlay drawer; closed content is inert and Escape/outside dismissal restores trigger focus. Desktop keeps inline history. The source list uses the shared SlidePanel (full-screen modal on mobile, bounded non-modal panel above tablet/desktop chrome). The transcript exposes explicit 처음/이전/다음/최신 history actions at every width instead of scroll-proximity loading; controls may wrap as one semantic group but never disappear behind hover. Chat settings has an explicit 44px return-to-chat action. Composer controls wrap before shrinking capability labels or clipping Search/send actions.

Provider model onboarding reuses existing `Button`, `Alert`, `Field`/input, `Pill`, and modal primitives; it introduces no palette, motion, or layer token. Discovery provenance and failure/empty/unsupported states stay in the provider's candidate panel. Exact IDs wrap without truncating identity. Registration review separates inactive save from price-pair-gated activation; provider token limits are advisory, not evidence of capability or successful inference. Capability overrides have their own explicit editor and source label. Controls and modal footer actions remain reachable at every breakpoint and wrap on narrow screens. The chat model picker keeps **목록 새로고침** in its header, shows refresh failures inline, and preserves the prior valid selection.

## Actions

Use `Button`: `primary`, `accent`, `secondary`, `subtle`, `ghost`, `outline`, `danger`, `danger-outline`, or `link`; and sizes `xs`, `sm`, `md`, `lg`, or `icon`. Warm `primary` is one highest-priority CTA per surface. Blue `accent` is create/save/run and other routine operational work. `secondary`/`outline` are neutral actions; `subtle` compact chrome; `ghost`/`icon` utility actions; `danger`/`danger-outline` destructive entry or confirmation; `link` inline navigation. `href` renders an anchor; a missing/falsy href renders a native button. Icon-only `Button size="icon"` requires `ariaLabel`.

Disabled anchors omit `href`, set `aria-disabled`, and leave the tab order with `tabindex="-1"`; the click handler also blocks navigation. `target="_blank"` anchors always add `noreferrer`, including official billing-console actions. Button has no loading prop: callers compose `disabled` with an accurate label.

`Button ariaPressed` exposes a boolean toggle state on native buttons. Chat's optional native API Search action uses this state and a 44px mobile touch target; built-in search models display a non-toggleable `Search · 기본` state. Capability badges in model lists describe support, not whether search ran on a specific answer.

Every label says what happens and keeps its name through the flow: a trigger labeled 삭제 leads to a confirmation whose affirmative button is also 삭제, not a generic 확인. `confirmDialog()` in `frontend/src/lib/stores/confirm.svelte.ts` passes only a message today and `ConfirmDialog` hardcodes 취소/확인, so naming the verb first requires extending that store and primitive with an optional confirm label, adding the primitive test, and updating this document.

## Forms

Compose forms with `Field` plus `TextInput`, `SelectInput`, or `TextareaInput`; use `FormModal` and `ConfirmDialog` for submit/cancel flows. `ToggleGroup` owns compact mutually exclusive filter/view choices: callers supply `value`, `options`, and `onchange` rather than recreating segmented controls. Field owns visible label/help/error copy and `for`/`id`; input primitives own placeholder, disabled, and focus appearance. `TextInput` accepts `inputmode` (`text`, `decimal`, `numeric`, `search`, `email`, `url`, `tel`) for touch keyboard hints such as credit-limit amounts; it is a hint only and never replaces server-side or caller-side validation. `Field` renders its help and error with the id `${for}-message`, and `TextInput`, `TextareaInput` and `SelectInput` default `aria-describedby` to that id whenever they are given an `id`, so the association forms without the caller wiring it. Pass `ariaDescribedBy` explicitly to point elsewhere, and `ariaInvalid` when the field is in error. Do not document imaginary error or loading props.

`SearchSelect` is the shared single-value picker for long named resource lists. Its trigger preserves the chosen label while the popover filters by label and stable identifier, exposes combobox/listbox semantics, supports ArrowUp/ArrowDown/Enter/Escape, and returns focus to the trigger after keyboard selection or dismissal. Loading and no-match copy stay inside the control. The popover portals to `document.body` as a viewport-fixed shared-popover layer, chooses the roomier side of the trigger, and bounds its list height so Card/table overflow cannot clip long catalogs. It remains width-contained on mobile; do not replace it with a full-height native `<select>` for user, project, or other long catalogs.

Any long OpenStack resource catalog picked inside a stacked settings list — including every `/admin/settings` resource policy — MUST use `SearchSelect` rather than a route-local absolute dropdown: a dropdown pinned below its input is clipped by the page bottom, so results at the end of a long settings page cannot be read or clicked. `SearchSelect` places the popover on the roomier side of the trigger, so a picker near the viewport bottom opens upward and remains fully visible. Optional `onopen` lets a caller lazily fetch or retry its catalog when the popover opens; it never changes placement, filtering, or dismissal behavior.

Offer choices over typing. A field whose valid values are an enumerable OpenStack catalog — datastore, version, flavor, availability zone, volume type — uses `SelectInput` or `SearchSelect`, and falls back to free text only when the catalog failed to load and `Field help` says so. A placeholder may only illustrate the shape of an expected value; any constraint the user must keep satisfying while typing — minimum length, allowed characters, unit — also appears in `Field help`, because the placeholder is gone at the first keystroke. Validate while the user is still in the form: a detected problem appears in `Field`'s `error` slot ahead of `FormModal`'s `onSubmit`, not only as a post-submit `Alert` or `Toast`. `TextInput type="password"` and every other secret input starts empty, never binds a server-returned secret, and never renders a stored secret as its value; that a secret is already stored is stated with `Pill` or `Field help`. `/admin/settings` carries only the global, infrequently changed defaults that `AdminLoginBrandingPanel` and `AdminResourcePoliciesPanel` already hold; a per-route filter, sort, column, page-size, or view control stays in that route's `ResourceToolbar` or `ToggleGroup` where its effect is visible.

## Feedback/overlays/tables

Use `Alert`, `Toast`, and `EmptyState` for feedback; `StatusChip` + `getStatusStyle` and `Pill` for status; `TableShell` for tabular data. Modal is the scrim/dismissal shell and `Card surface="modal"` is the panel surface. Table density is normal `0.75rem × 1rem` or compact `0.5rem × 0.75rem`. UsageBar default thresholds are warning 80 and danger 95; it accepts `percent` or `value`/`max`, clamps invalid or out-of-range percentages to `0–100`, and for `max={-1}` labels the quota `무제한` without a percentage or fill. Use `UsageBar`, `QuotaBar`, or `CapacityBar` instead of route-specific bars.

`UsageRing` is the compact inline counterpart to `UsageBar`: use it only where a quantitative meter must share a narrow control row, such as the chat composer. It uses the same threshold contract, remains a `role="meter"` with an explicit text equivalent, and never replaces the full UsageBar on settings, quota, or detail surfaces.

Feedback lives in the interface, not in an interrupting dialog. A data surface paints `frontend/src/lib/components/LoadingSkeleton.svelte` — which sits outside `ui/` and is referenced by path, not as a primitive — or its own `TableShell` header plus placeholder rows, from first render and shows `EmptyState` only after the request resolves with zero results, never while it is still pending. A failed session, catalog, or first-load request detected while mounting is reported with an inline `Alert` inside the route's `PageShell`, never by opening `ConfirmDialog` or `Modal` before the user has acted. Failure copy in `Alert` or `Toast` names the operation that failed and the step that resolves it, and exposes that step through `Alert`'s `actions` snippet or the toast `action.label` whenever a retry, settings, or navigation path exists, instead of a bare `오류가 발생했습니다` fallback.

`ConfirmDialog` is reserved for operations no surface can reverse. An action whose reversal is already reachable from the same controller with the arguments in hand — `setDeleteOnTermination(volumeId, !next)`, or `attachVolume` after `detachVolume` — proceeds without a dialog and reports through `toast` with a `ToastAction` that performs the reversal and an explicit `duration` longer than the 4000ms default. Because `ConfirmDialog` renders only `dialogState.message` above its hardcoded pair, that message is the only text that can predict the outcome: every caller names the specific resource and states that the operation cannot be reversed.

A modal holds one scoped task. `FormModal` keeps that task inside its `min(calc(100vw - 2rem), 28rem)` frame with no nested step hierarchy; multistep or browse-heavy work belongs in `SlidePanel` or its own route. A caller that overrides `FormModal`'s `actions` snippet still renders a non-confirming exit, because the override replaces the default cancel/submit pair entirely, and `Modal dismissible={false}` is permitted only while an action is in flight — the `dismissible={!submitting}` pattern — never as the resting state of an open dialog. A `SlidePanel`'s default `width` presents its primary content and controls without resizing, because the drag handle is gated behind `resizable && isDesktop` and the persisted `storageKey` width applies only at `md` and above; no required control may be reachable only by widening the panel.

Admin service lists compose Field, TextInput, SelectInput, Button and compact TableShell for search, independent exact-value filters, filtered/total counts and reset. Sortable column headers use a keyboard-operable Button, a visible direction indicator and `aria-sort` on the `th`; text sorts naturally (host2 before host10), numeric capacity numerically, and unknown values remain distinct and sort last. Controls wrap from one column on mobile to two on tablet and a compact multi-column desktop toolbar. Filter/sort selections belong to each tab and survive background refresh and tab switches; refresh leaves existing rows and controls interactive. A no-match result retains controls and a reset path instead of looking like an empty service response.

Admin user quotas load one 20-user Keystone marker page at a time and place the shared `Pagination` control below both the desktop table and the equivalent `<1024px` card view. Search filters only the loaded page and says so explicitly. Lumen quota records join only to users on that page, so an unloaded later-page user is never presented as an unknown account. Previous/next navigation preserves all per-user actions and the current page across quota mutations.

Admin database inventory is a Trove resource surface, not an infrastructure-monitoring surface. Its all-project table identifies each tenant-created instance by owning project and uses `Alert` for a failed management lookup instead of presenting failure as an empty inventory. Generic `mysqld_exporter` panels belong only to the administrator monitoring route; never place control-plane database metrics beside tenant Trove resources.

## Status & data visualization

Operational status uses exact, case-sensitive `getStatusStyle(status: string | null | undefined)` and its five tones; unknown or falsy status is neutral. Status conveys label plus tone and, where applicable, transition dot; color alone is never state. Charts use the six ordinal `CHART_COLORS`; topology preserves its domain colors. The topology canvas view alternates tenant zones between `--color-topology-internal` and `--color-topology-internal-2`, uses `--color-topology-gateway` only for L3 device stripes and glyphs (never as a status tone), and paints zone fills with `color-mix()` at `--topology-zone-fill-alpha` (`--topology-zone-fill-alpha-active` when selected) over the `--color-topology-grid-minor`/`--color-topology-grid-major` grid. A trunk badge renders only when it carries information no single switch card does — `trunkNetIds` of at least two, and at most one badge per router. That condition holds only for an external or shared provider-tier uplink, so the one caption that can ever render is `하위망 합산`, which names its scope in visible text: it sums only the tenant networks directly behind that router, never provider-wide totals. A lower tenant switch link is not badged at all; its switch card carries the number. A trunk over one network resolves to that network's own `traffic.networks[netId]`, which the adjacent switch card already prints, and the badge sits at the router↔switch midpoint, which is not required to fall inside its own zone; tenant trunks always carry exactly one network and are therefore never badged. Badges hide below `k < 0.5`, the same threshold at which node cards drop `.node-sub`, so no zoom level shows a badge beside cards that have been stripped of their own rates. Below that threshold the canvas carries no traffic figures; zone-label CIDR and admin pills are HUD and stay.

토폴로지 케이블 생성은 accent 색의 출력 포트와 가능한 입력 대상 테두리로만 affordance를 보인다. 포트는 카드 경계를 0.625rem 넘을 수 있어야 하므로 카드 컨테이너는 clipping하지 않고, NIC 목록만 내부 overflow를 자른다. 드래그 중 임시 케이블은 accent 점선과 endpoint dot을 사용하며 pointer event를 가로채지 않는다. 이 상태 표시는 선택/오류 status tone을 대체하지 않고 `Escape` 또는 무효 drop에서 즉시 사라진다.

A surface that renders `Spark` prints the series' rendered minimum and maximum in adjacent text, as the dashboard and usage routes do, because `Spark` maps each series onto `max - min` and would otherwise draw a narrow band as a full-height swing; a fixed lower bound requires extending `Spark`, adding its primitive test, and updating this document first. A chart plotting more than one series names every series in visible text, as `TrafficSparkline`'s `▼ 수신`/`▲ 송신` legend does with a glyph as well as a word; ordinal position in `CHART_COLORS` is never the only identifier of a series. `Spark`, `Donut`, and `QuotaDonut` never leave an unnamed graphic in the accessibility tree: either the plotted SVG carries a succinct accessible name, the way `UsageRing` pairs `role="meter"` with `aria-label`/`aria-valuetext` over an `aria-hidden` inner SVG, or the SVG is `aria-hidden` and the chart's message is carried in adjacent readable text.

## Motion

`MOTION_CSS_VAR`, `MOTION_DURATION_MS`, and `REDUCED_MOTION_QUERY` are the shared vocabulary. Fast `--motion-duration-fast: 120ms` + `--motion-ease-standard: ease` is hover/focus/color feedback. Base `--motion-duration-base: 160ms` is control movement, compact fills, and fades. Panel `--motion-duration-panel: 200ms` + `--motion-ease-out: ease-out` is drawer/fly/pop. Data `--motion-duration-data: 500ms` is long-form resource/build progress. Status pulse `--motion-duration-status-pulse: 1400ms` + `--motion-ease-in-out: ease-in-out` is status dots.

Animate opacity, translate, or scale only; never animate layout dimensions. Hover is decoration, never the only status signal. Repeating animation is limited to loading, progress, and status. `prefersReducedMotion()` and `motionDuration()` make JavaScript transitions immediate. The global reduced-motion contract sets all five duration variables plus Tailwind `--default-transition-duration` and `--default-animation-duration` to `0.01ms`, scroll to `auto`, and universally overrides animation/transition duration and delay.

A new duration or easing curve is defined in `layout.css`, exposed through `MOTION_CSS_VAR`/`MOTION_DURATION_MS`, and given its `designSystemRules` test entry before any feature uses it. Motion the CSS contract cannot reach — `Element.animate()`, `requestAnimationFrame` loops, and any explicit `scrollIntoView`/`scrollTo` with `behavior: 'smooth'` — branches on `prefersReducedMotion()` at the call site, because the reduced-motion block overrides only CSS `animation-*`/`transition-*` and its `scroll-behavior: auto` loses to an explicit `behavior` argument; the ChatPanel composer nudge is the compliant pattern and the unguarded `scrollIntoView` in `frontend/src/routes/dashboard/notifications/+page.svelte` is known debt, not an exception. An overlay stays cancellable while its own transition runs: `SlidePanel` and `ProjectQuotaPanel` fire `onClose` immediately from the scrim and the close control rather than deferring to a transition-end event or timer, and no control is disabled because an entrance or exit transition is running — disabling for in-flight work such as an active save is unrelated and remains allowed.

Named motion exceptions: `--landing-ease`; ChatPanel composer `cubic-bezier(0.22, 1, 0.36, 1)`; QuotaDonut `duration-700`; 600ms landing reveal; 7-second tutorial hint; `0.8–1.2s` linear loading loops; and 토폴로지 캔버스 패킷 흐름 시뮬레이션 (기본 on, 툴바 토글로 끌 수 있음, prefers-reduced-motion 시 완전 비활성, rAF 기반 transform 이동). Do not copy exceptions into ordinary components.

## Editorial surfaces

`--gradient-editorial-canvas`, `--pattern-editorial-grid`, `--gradient-editorial-grid-mask`, `--gradient-editorial-cta`, and `--color-surface-editorial-media` belong to public/editorial surfaces. Approved external SVG plates may retain their embedded palette only when loaded through `<img>`. Approved panel composition: `Card surface="subtle"` is the surface around semantic outer capability/workflow articles; the method matrix is one Card around direct semantic step articles.

The public landing page is a research-operations surface, not a generic campaign template. Its signature is the interactive operations board: a selected research request is shown passing through policy checks into allocated infrastructure and a reusable output. IBM Plex Sans KR carries hero, section, capability, quotation, and contact display headings; Pretendard carries explanations, actions, and product UI; `--font-mono` is limited to timestamps, resource identifiers, compact status labels, and other operational metadata. Landing display type uses medium or semibold weights, restrained negative tracking, and fluid sizes between `2.75rem–4.25rem` for the hero, `2rem–3.75rem` for section headings, and `1.25rem–2rem` for editorial card headings. These public display sizes and the display family do not extend the application-console type scale. The landing surface also carries its own small-type tier below the console floor: compact labels, eyebrows, section labels, indices and operational metadata are `0.6875rem`, in `--font-mono` where they are Latin identifiers and in `--font-sans` where they are ordinary label copy. The remaining `0.625rem` figure captions, workflow meta, stage bar and footer brand line are pre-existing usages that new work does not extend; `aria-hidden` rails and icon glyphs carry no type floor because they are not text. New landing work uses `0.6875rem` only for a compact label and `0.75rem` or above for reading copy.

Landing responsive composition follows the global tiers exactly. Mobile stacks the hero copy, scenario controls, policy checks, allocated resource, and reusable output in one reading order; the brand and compact console action share the first navigation row while 44px-tall navigation links scroll horizontally below them. Tablet keeps the hero copy above the full-width operations board, places section labels above their headings, and uses two columns only for capability and method pairs. Desktop places the hero copy beside the operations board and may move section labels into a stable left rail. The board retains its readable two-row desktop flow until the `xl` density refinement (`≥1280px`); only then may request, policy, and allocation expand into one row. The four capability stories form one divided two-by-two service matrix rather than cards with unequal spans: every cell has the same geometry, static cells do not use hover affordances, and artwork is contained inside a bounded media plate without cropping embedded captions. Workflow filters remain sticky only while their adjacent list is visible. Product artwork is evidence inside bounded console frames, never a rotated decorative collage. Static workflow summaries form one divided list rather than a stack of decorative cards. All content, actions, filter state, captions, and contact paths remain available at every tier.

## Chat messages

`ChatBubble` is the chat-message primitive. It supplies `chat-start`, `chat-end`, header, bubble, and optional action footer; features provide only content and actions. It owns `--chat-message-gap`, `--chat-message-meta-gap`, `--chat-message-meta-inset`, `--chat-message-meta-size`, `--chat-message-radius`, `--chat-message-directional-corner`, `--chat-message-padding-block`, `--chat-message-padding-inline`, `--chat-message-assistant-max-inline`, and `--chat-message-user-max-inline`. Do not recreate route-specific bubbles, sizes, or colors.

The transcript renders at most three 40-message active-path pages. Prepending preserves the first visible message's viewport offset rather than jumping to the top. Loading a fourth page evicts only the opposite edge and leaves that edge recoverable through its cursor. New run completion while reading an older window does not steal scroll or inject a draft into historical content; a visible **새 응답이 도착했습니다** action returns to the latest page. Sending from an older window first resolves the live edge, then clears/submits the draft.

Message version arrows consume server-projected previous/next sibling IDs; the browser does not download or reconstruct the historical graph. Cursor conflict is an inline `Alert` followed by one latest-window recovery request. History navigation stays disabled during its one in-flight request and stale selection/project/mutation responses never repaint the transcript.

The public Claude Gateway authorization shell uses the same `Card`, `Field`, `TextInput`, `StatusChip`, `Alert`, and `Button` primitives as authenticated settings. It remains a single readable column at mobile/tablet/desktop, names both fixed scopes and the 24-hour credential lifetime, and keeps deny distinct from the primary approve action. A complete-link code is scrubbed from the URL before rendering; login/project-selection return to the shell, while manual entry remains available. Approval success and denial replace the form with a terminal status instead of leaving reusable actions.

Assistant citation sources precede the answer and its reasoning/tool activity, never trail the response. Keep provider order and numbering in a horizontally scrollable source row with safe HTTP(S) links, title/domain and bounded returned snippets; document citations never acquire fabricated URLs. The row scrolls within the bubble rather than widening the transcript. The header source panel shows the loaded conversation's deduplicated source titles, URLs and full bounded snippets, preserving visited-link distinction and showing an honest empty state when no metadata was returned/stored.

Context capacity distinguishes a tokenizer count from an estimate and shows remaining input tokens. Unknown model limits, unmeasurable input, invalid budgets and request failures are distinct explanations available by keyboard focus and touch, not a title-only tooltip. An unknown value never renders a zero/full meter; transient request errors invalidate stale preview values without treating them as conversation failures.

The context inspector opens from the composer into the shared SlidePanel, preserving the same mobile-modal and tablet/desktop non-modal contract as sources. It shows included component counts and safe source names separately from deferred material. The table's percentages use the full model context limit, not the smaller input budget; output reserve, compaction/safety buffer and remaining input capacity are separate rows. A UsageBar summarizes the known input share. Incomplete counts suppress an exact free-space claim, unknown windows suppress all percentages, and estimates retain their measurement label. Existing events without a breakdown show an explicit metadata-unavailable state, never invented categories. No new color or overlay primitive is introduced.

Uncounted material that may enter the execution request is not labeled as merely deferred: preloaded-but-undiscovered MCP schemas and non-text attachments get a separate unresolved group. Unknown model capacity must not hide safe composition names/counts. Component rows preserve a 44px disclosure target without stacking unnecessary vertical padding.

## Resource selection

Show a checkbox on both desktop and touch for selectable rows/cards. `SelectionCheckbox` owns checked, indeterminate, disabled, and unavailable-X semantics; `SelectionToolbar` owns the select-all control, selected count, and `onToggle`; `BulkSelectionOverlay` owns the selected-count, busy, and bulk-action presentation. `ActionMenu` owns the overflow trigger, fixed popover placement, outside-click/Escape dismissal; callers own its `open`, `onopen`, and `onclose` state. Unavailable resources show a disabled circular X in the same position and provide the reason. A screen owns one visible resource-domain selection state; tab/filter/project/domain changes clear selections outside the result. Use `BulkSelectionOverlay`, `bulk-selection-page`, `resource-selection-surface`, and `data-selected`; select-all includes only selectable IDs.

Admin all-volumes selection is marker-page scoped. Filters, page size, pagination, and admin project-scope changes clear it. Bulk deletion uses one confirmation, reports per-resource partial success, removes only successful IDs, and retains failures. Status cards and status-select options are data-driven from positive cluster-wide counts; if an active status reaches zero, return to the total filter instead of retaining a hidden filter.

A `SelectionCheckbox` or row-level selection control paints `--focus-ring` only under `:focus-visible` and signals pointer hover with its own border or surface change, so the keyboard-focused control stays identifiable while the pointer rests on a different row. When a keyboard activation of 취소 or of a bulk action drops the count to zero and unmounts `BulkSelectionOverlay`, focus moves to a stable remaining control — the `SelectionToolbar` select-all checkbox or the originating row — never to `document.body`; pointer-initiated dismissal keeps the default of simply letting the focus indicator disappear.

## Accessibility

Never communicate status, selection, loading, or disabled state through color or animation alone: pair visible text and the relevant attribute/reason. Maintain visible keyboard focus with `--focus-ring`. Every `role="dialog"` surface reaches the `dialogFocus` action (`frontend/src/lib/utils/dialogFocus.ts`), which is now the single implementation of dismissal and focus containment: it moves focus into the dialog on open, marks every ancestor-branch sibling `inert` so `aria-modal="true"` is a true claim, closes the top layer only on Escape, and restores focus to the opener. A dismissal handler declared on the overlay element itself is the anti-pattern this replaced — focus never entered those overlays, so the handler could not fire and the modal boundary sealed assistive technology out of a surface it could not leave. A new floating surface wires `use:dialogFocus` rather than its own `onkeydown`, and passes the open expression as `enabled` when the element is not already inside an `{#if}`.

Normal-sized public/editorial labels use `--color-ink-2`, `--color-warm-text`, or `--color-state-success-text` so both themes retain WCAG AA contrast without changing the dark brand palette. Reserve `--color-ink-3` for disabled text and raw `--color-warm` / state tones for large display text or non-text decoration.

Type is declared in `rem` rather than arbitrary `text-[Npx]` values, and every new or materially changed surface is verified at 200% browser zoom with `PageShell` hierarchy intact, `TableShell` headers readable, and every action still reachable; the absolute `body { font-size: 14px }` in `layout.css` and the `Sidebar`, `AdminSidebar` and `CmdPalette` islands are pre-existing usages that new work does not extend. Console type below the `0.75rem` floor was swept out of the rest of the application: no surface outside those three islands declares 8, 9, 10, 11 or 12 pixels any more. What remains off-ladder and is deliberately left alone is `text-[13px]`, which renders at the `0.8125rem` row tier and has no Tailwind step to convert to without inventing a spelling, and the `text-[15px]`/`text-[26px]`/`text-[28px]` display sizes, which sit above the ladder's `1.25rem` top and need a documented display token rather than a swap. A row, card, or code surface must not reveal a control by pointer hover alone: an action behind `group-hover` also appears on keyboard focus with `--focus-ring` visible, or stays permanently visible the way `ActionMenu` keeps its trigger — `ObjectFlatTable`, `ObjectTreeTable`, and `K3sYamlView` are existing debt, not the pattern to copy. A chart, meter, or multi-series surface carries series identity and magnitude in an encoding a colorblind reader perceives without distinguishing hues — an adjacent label and value the way `QuotaDonut` renders its `label`, or a distinct shape or pattern per series — and a screen-reader equivalent never substitutes for that visible encoding.

## New UI entity workflow & legacy debt

1. 새 색상·gradient·badge tone·table density·form control·card treatment가 필요하면 feature file 작성 전에 `layout.css`, `frontend/src/lib/design/tokens.ts`, `frontend/src/lib/components/ui/*`, tests, `DESIGN.md`를 먼저 갱신한다. 새 motion duration·easing curve도 같은 순서를 따른다.
2. Primitive token/test work precedes feature composition; then run the visual-debt guardrail.
3. 새 route/component file은 raw hex, `bg-[#...]`, raw palette classes(`bg-blue-600`, `text-gray-400`, `border-red-700` 등)를 직접 추가하지 않는다. Existing debt is bounded by `frontend/src/lib/design/legacyVisualDebt.ts`; reduce it in separate visual-regression work rather than extending it.
4. Use `StatusChip` + `frontend/src/lib/config/statusColors.ts` for operational status. New inline ternary status colors are prohibited.
5. Use `frontend/src/lib/components/ui` for action, modal, table, form, card, and alert. If a primitive is insufficient, extend that primitive and update its tests and this document first.
6. UI/UX 변경은 `Apple HIG adoption and non-goals`의 원칙 필터와 비채택 목록을 먼저 확인한다. 대비·색상 문제는 finding으로 기록하고 기존 토큰 값을 바꾸지 않는다.
