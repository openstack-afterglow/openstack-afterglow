# 사용자 서비스 가이드

Afterglow의 사용자 문서 경로는 **배포된 콘솔 origin의 `/docs`**다. 개발자 API 참고 자료·설치 문서와 분리하여 현재 콘솔에서 자원을 준비하고 사용하는 방법을 설명한다. 메인 페이지의 **Docs / 사용 가이드**와 사용자 콘솔 헤더·전체 메뉴의 **Docs · 사용 가이드**, 커맨드 팔레트에서 이동한다.

문서를 읽는 데 로그인이나 프로젝트 선택은 필요하지 않다. 실제 콘솔 작업에는 인증, 현재 프로젝트의 권한·쿼터와 해당 서비스 활성화가 필요하다. 문서가 있다는 사실은 특정 배포의 서비스 설치·가용성 또는 자원 생성 성공을 뜻하지 않는다.

## 서비스별 사용자 IAM

콘솔 **Docs → 시작하기 → IAM · 프로젝트 권한** 또는 `/docs/iam`에서 사용자별 역할과 기능 조건을 확인합니다. Lumen·Drover·Waygate·Palimpsest는 표준 `reader`가 허용된 리소스를 조회/읽기하고 `member` 이상이 프로젝트 리소스를 생성·관리합니다. 서비스별 등급·세부 역할은 따로 배정하지 않습니다. 조직 manager·프로젝트 owner/admin의 IAM 책임, 사용자/private 소유권·원래 credential/키 scope 및 전역 관리 권한은 구분합니다.

상세 정본은 [`iamGuide.ts`](../frontend/src/lib/docs/iamGuide.ts)이며 각 서비스 가이드에서 연결합니다. 실제 core/project/custom 역할 graph, MCP의 명시적 동의·키 scope·native 조회 장애와 권한 거부를 설명합니다. 기존 서비스 역할 데이터는 자동 삭제하지 않으며 retired 역할을 담은 pending 초대는 표준 역할로 재발급해야 합니다. 문서는 현재 source 기본 정책이며 운영 정책·IAM·서비스 배포 완료를 뜻하지 않습니다.

프로젝트 역할 그래프는 실제 상위 역할에서 포함되는 하위 역할과 native `member`·`reader` 가지를 표시합니다. 서비스별로 가짜 역할 계층을 더 만들지 않습니다. 모바일에서는 세로로 읽고 화면낭독기에는 동일한 방향 관계를 제공합니다. 이 graph와 별개로 각 native 서비스가 현재 역할·리소스 소유권·원래 자격 범위와 정책을 다시 검사합니다.

## 계정·개인 공간·조직

로그인은 사용자 이름 또는 이메일과 비밀번호만 입력하면 됩니다. 회원가입은 이메일로 받은 인증 링크를 연 뒤 사용자 이름과 비밀번호를 정하며, 이미 사용 중인 이름이나 이메일로 새 계정을 만들 수 없습니다. SSO 제공자가 이메일 인증을 확인하고 그 주소가 기존 계정과 일치하면 같은 계정으로 자동 로그인합니다. 확인되지 않은 이메일이나 기존 연결의 충돌은 자동 병합하지 않으며 관리자 확인이 필요합니다. 새 계정은 본인만 사용할 수 있는 개인 프로젝트에서 시작하고 기존 계정의 비밀번호·권한·자원을 초기화하지 않습니다. 개인 프로젝트 이름은 자동 생성되므로 내부 도메인 이름이나 프로젝트 이름을 지정할 필요가 없습니다.

시스템 관리자도 일반 사용자와 같이 본인의 검증된 기본 개인 프로젝트에서 시작합니다. **계정 설정 → 로그인 작업 공간**에서 마지막 도메인·프로젝트 재연결을 켜고 명시 저장하면 이후 로그인마다 해당 pair의 현재 권한을 확인해 복원합니다. 철회·삭제·비활성이면 개인 프로젝트로 돌아가지만 directory 장애는 오류로 구분합니다. 원래 계정 소속을 바꾸거나 조직 권한을 자동 추가하지 않으며 설정 보존은 서버 Redis 내구성 정책을 따릅니다.

사용자 페이지에서는 관리자 계정도 본인이 실제 권한을 가진 도메인·프로젝트만 선택합니다. 리소스 선택 창에 계정의 내부 소속 도메인은 표시하지 않습니다. 관리자 모드의 상단·모바일 메뉴에는 전역 리소스 선택기가 없으며, 각 관리 화면에 필요한 조회 필터만 사용합니다.

전체 메뉴 맨 위의 **Hub**는 개요·사용량·사용량 리포트·활동·토폴로지를 항상 보여줍니다. 관리자·사용자 모두 **모든 서비스**의 카테고리 목록은 메뉴를 열 때부터 보입니다. 카테고리를 눌러 하위 서비스를 펼치거나 검색으로 찾습니다. 별 버튼으로 추가한 목적지는 Hub 아래 **즐겨찾기**에 유지됩니다. 기존 바로가기 설정은 그대로 보존하며 계정과 사용자/관리자 모드별입니다. 즐겨찾기는 권한이 없거나 비활성화된 서비스를 열어 주지는 않습니다.

**VM 생성**을 열면 먼저 리소스 한도·호스트 용량, 사용 가능한 GPU, 저장 구성 이력과 사양 목록을 확인하는 준비 화면이 나옵니다. 사용자가 제공한 `output/afterglow-loading/index.html`의 canvas 장면을 따라 문자만으로 만든 빛의 링·디지털 문자 비·물결 반사를 창 전체에 채우며, **실제로 아직 확인 중인 작업**은 링의 정확한 중심에 읽을 수 있는 텍스트로 놓입니다. 장면 밖의 제목·회색 여백·안내 footer·카드 테두리나 별도 로고·브랜드 문구는 표시하지 않습니다. 우상단 닫기와 Escape로 계속 닫을 수 있습니다. 배경·문자·작업 문구는 현재 콘솔의 밝은/어두운 모드와 색상 token을 따르고 창이 열린 상태에서 모드를 바꾸면 바로 반영합니다. 배경의 공개 기술 용어·문자는 장식이며 실제 자원값·진행률·예상 시간이 아닙니다. 작업 문구는 실제 조회가 완료/실패할 때만 바뀝니다. 모션 감소 설정에서는 정적 장면과 같은 작업 문구를 제공하고, 화면 밖이나 숨긴 탭에서는 장식 반복을 멈춥니다. Canvas를 사용할 수 없어도 작업 문구·실패 안내·재시도는 남습니다. 준비가 끝나면 기존 제목·단계 표시·본문 여백·진행 버튼을 가진 사양 선택 화면이 열립니다. 이미지 목록도 이 준비와 병렬로 미리 요청하므로 조회가 완료됐다면 다음 이미지 단계는 같은 결과를 바로 사용합니다. 이미지가 아직 느리거나 실패한 경우 해당 단계의 기존 로딩·재시도를 유지하며 이미지 때문에 사양 준비를 막지 않습니다. 실패하면 장면 안의 **준비 다시 시도**로 실패한 조회만 다시 확인하거나 창을 닫을 수 있습니다. 이후 자동 새로고침은 작업 중인 구성 화면을 가리지 않습니다.

다른 목록·상세·로그인·AI 작업의 조회/처리 대기도 같은 문자 링·비·반사 장면을 사용합니다. 처음 데이터를 기다리는 영역은 해당 페이지/패널을 채우고, 버튼·검색 선택·행 작업과 새로고침은 같은 장면의 작은 정적 frame과 실제 작업 문구로 표시합니다. 이미 읽은 목록과 편집 중 내용은 정상 background 새로고침 때문에 전체 로딩 화면으로 바뀌지 않습니다. 작은 장면이 움직이지 않아도 문구·버튼의 대기 상태가 유지되는 동안은 작업 중이며, 장식의 문자/링은 진행률·남은 시간·성공을 뜻하지 않습니다. 실제 전송 비율·배포 단계·오류/재시도는 기존대로 따로 확인하세요.

**플랫폼 동작 관측**

관리자 **운영 이벤트**는 로그인 성공/실패, 요청·인증의 처리 단계와 중간 오류, 콘솔 버튼·링크·폼·페이지 이동 관측을 출처별로 표시합니다. Browser의 **관측됨**은 버튼이 눌렸다는 신고이며 리소스 생성·삭제·로그인 성공을 의미하지 않습니다. 상세에서 서버 요청 ID 또는 interaction UUID로 관련 단계와 HTTP 상태·기간·구조화된 오류를 확인하고 도메인/프로젝트·사용자·출처·기간으로 범위를 좁힙니다. 익명 실패에는 검증되지 않은 계정 이름을 붙이지 않으므로 전체 범위에서만 보일 수 있습니다.

입력값·선택값·페이지 본문·비밀번호·토큰·URL query/hash·요청/응답 본문·원문 오류는 이 관측에 수집하지 않습니다. 동작 위치는 페이지 종류·control 유형/순번·정제된 이동 목적지로 구분합니다. Offline·브라우저 종료·차단기·DB 장애나 로그인/프로젝트 교체에서 일부가 누락될 수 있으며 현재 브라우저의 전송/누락 수가 플랫폼 전체 수집률은 아닙니다. 과거 비수집 사건을 만들어내거나 사용자 입력/화면을 재생하는 기능이 아닙니다.

관리자 **Identity → 사용자**에서 정확한 계정 소속 도메인을 선택한 뒤 행·카드의 **삭제**로 불필요한 native 계정을 제거할 수 있습니다. 확인 창의 이름·전체 사용자 ID·도메인을 대조하고 **전체 ID**를 입력해야 삭제됩니다. 자기 계정·운영 서비스/관리 권위 계정·소유 프로젝트나 미완료 작업이 있는 계정은 보호하며, 먼저 해당 권한·소유권·작업을 정리해야 합니다. 삭제는 세션을 폐기하지만 프로젝트·VM·볼륨을 같이 삭제하지 않습니다. 알 수 없는 이름이라는 이유로 자동 삭제하지 않으며, 응답이 불확실하면 재시도 대신 창을 닫고 현재 목록을 다시 확인하세요.

자동 생성된 개인 프로젝트의 표시 이름은 [`/dashboard/project-settings`](/dashboard/project-settings)를 직접 열어 **프로젝트 표시 이름**에서 바꿀 수 있습니다. 선택 창의 **활성 프로젝트 설정** 버튼은 제거했으며, 현재 이 페이지는 별도 메뉴 진입점 없이 URL로 접근합니다. 저장하면 상단·선택 목록과 다음 로그인에도 같은 이름이 표시됩니다. 내부 원래 이름·프로젝트 ID·권한·quota·기존 자원은 바뀌지 않으며 다른 사용자의 개인 프로젝트는 수정할 수 없습니다.

제공 기본 개인 한도는 **2 vCPU·4 GiB RAM·1024 GiB 블록 스토리지**입니다. 실제1TiB 디스크를 미리 만드는 것이 아니라 볼륨을 생성할 수 있는 quota입니다. 기존 관리자 맞춤 policy와 이미 생성된 프로젝트를 자동으로 덮어쓰지 않습니다. 관리자는 설정의 제공 기본값을 draft에 채워 저장하고, 기존 개인 프로젝트 목록에서 현재 사용량+예약량을 미리 확인해 프로젝트별로 적용합니다. 새 한도보다 사용 중인 자원이 많으면 감축은 차단하며 리소스를 삭제하지 않습니다.

조직은 별도의 리소스 도메인이다. 생성 기능과 소유 조직 수 제한은 운영자 정책을 따르고, 가입은 현재 manager의 초대 수락 또는 신뢰된 OIDC 가입 규칙을 따른다. 같은 로그인 제공자를 쓴다는 이유만으로 조직에 가입하지 않으며 일반 자동 가입은 reader 권한만 부여한다. 초대 대상 조직은 내 계정의 원래 소속을 바꾸지 않는다. 리소스 선택기로 이미 가입한 조직을 살펴보는 것만으로 세션이 바뀌지 않고, 프로젝트를 명시적으로 선택할 때 작업 범위가 전환된다. `accounts`와 `personal`의 이름 변경·비활성화는 허용하지 않는다.

리소스 선택 창의 도메인 목록은 기본적으로 **Personal을 맨 위**에 표시합니다. 표시 설정에서 직접 저장한 순서는 유지하며 정렬만으로 활성 도메인이 바뀌지 않습니다. 하단에는 허용된 **도메인 만들기**, **프로젝트 만들기**를 모았습니다. 프로젝트 만들기는 둘러보는 도메인의 현재 생성 권한을 확인하며, 도메인 만들기는 별도 운영자 정책을 따릅니다. **도메인으로 계속**, **활성 프로젝트 설정** 버튼은 선택 창에서 제공하지 않습니다.

### 조직 IAM의 사용자 관리·프로젝트 관리

- **사용자 → 도메인에서 내보내기**는 현재 조직의 프로젝트·그룹 접근만 회수합니다. 계정, VM·볼륨 및 다른 도메인 권한은 보존하며 관리자 Identity의 계정 삭제와 다릅니다. 현재 도메인이 계정 홈이면 내보낼 수 없습니다. 소유자·manager는 먼저 권한을 이전하고 다른 범위에도 연결된 그룹은 시스템 관리자에게 검토를 요청하세요. 불명 결과는 새로고침하여 권한을 확인한 뒤 판단합니다.
- **프로젝트 관리 → 프로젝트 만들기** 또는 상단 **리소스 선택 → 프로젝트 만들기**에서 생성합니다. 해당 조직의 Default 프로젝트에 현재 `manager` 또는 `project_creator`가 있어야 합니다. Manager는 별도 creator 프리셋 없이도 생성할 수 있습니다. Creator는 본인이 소유하거나 관리 권한을 가진 프로젝트만 관리하며, 다른 프로젝트의 관리는 리소스 선택기로 명시적으로 전환한 뒤 수행합니다. Creator라는 이유로 사용자 관리·초대·로그인 정책을 관리하지 못합니다. 사용자별 프로젝트 역할 편집과 소유권 이전·안전 삭제는 각 전용 작업을 사용합니다.
- **이메일 초대**에서는 먼저 이메일을 입력하고 **초대 이메일 발송**을 누릅니다. 이어지는 창에서 여러 프로젝트와 각 역할을 선택하고 최종 발송합니다. 이메일 한 통의 링크로 일괄 할당하며 선택하지 않아도 조직 Default 읽기 권한을 받습니다. 창 취소는 이메일을 보내지 않습니다.
- **모니터링 및 배분**은 현재 도메인 전체 관측, 프로젝트·사용자 귀속, Nova 할당 추세, 할당 예산/기본값/프로젝트 한도 편집을 한 곳에 둡니다. 예측은 최근7일 할당 이력의30일 추세이지 실제 이용률이나 수요 보장이 아닙니다. 미지원·거부·누락은0과 다르게 표시하며 일부 조회가 실패해도 다른 정상 영역은 유지됩니다.

내보내기는 잘못 연결된 다른 홈 도메인 계정의 현재 접근을 정리하는 용도입니다. **영구 차단이 아니며 SSO 자동 가입 규칙과 기존 초대는 유지합니다.** 다음 SSO 로그인이나 초대 수락으로 재가입할 수 있습니다. 계정 연결 자체의 이전/병합은 별도 작업입니다.

### 도메인 CPU·GPU 공용 풀

조직은 **도메인 공용 CPU·RAM·GPU 모델별 정책**을 설정하고 모든 소속 프로젝트에서 공유할 수 있습니다. 시스템 관리자가 pool을 설정하고 해당 도메인의 manager/system-admin은 프로젝트별 추가 상한을 정합니다. 프로젝트 상한은 예약이 아니며 GPU 모델 allocation이 허용하는 flavor 접근은 모든 enabled 프로젝트에 자동 동기화됩니다. 새 프로젝트도 다음 동기화에 포함합니다. CPU/RAM domain 한도를 비워도 native 프로젝트 quota는 계속 적용됩니다.

GPU 사용권한이 있어도 **Nova 프로젝트 CPU/RAM quota**가 부족하면 생성이 차단됩니다. 관리자 프로젝트 할당량 또는 조직 manager의 프로젝트 배분에서 native quota를 명시 조정하세요. Domain pool/project cap 입력은 이 native quota를 바꾸지 않습니다. 새 프로젝트 CPU/RAM 기본값도 별도 저장하며 pool 중지/조회 장애와 독립적으로 편집할 수 있습니다. 기존 allocation 예산·사용량/예약량 검증은 유지하고 부족한 quota를 자동 증액하지 않습니다.

관리자 도메인 상세와 IAM **모니터링 및 배분**에서 한도·실제 할당량·잔여량·선택적 프로젝트 상한을 확인하세요. 미확인은0이 아닙니다. **일시 중지**는 Afterglow의 신규 요청을 차단하고 기존 VM/볼륨을 삭제하지 않습니다. 직접 OpenStack CLI/API·다른 서비스의 요청까지 domain 정책을 전역 집행하는 기능은 아닙니다.

도메인 manager는 IAM **모니터링 및 배분**에서 프로젝트별 GPU 상한을 설정하거나 프로젝트와 GPU 그룹을 선택해 추가 장 수를 요청하고 처리 상태를 확인할 수 있습니다. 시스템 관리자는 관리자 **할당량**의 요청 목록에서 대상 도메인을 열어 기존 공용 풀과 필요하면 프로젝트 상한을 직접 조정합니다. 요청의 **처리 완료**는 현재 두 상한이 요청 목표 이상인지 확인한 기록이며 버튼이 quota를 자동 변경하지 않습니다. 거절 사유는 요청 목록에서 확인합니다. 여러 프로젝트가 공용 한도를 사용하므로 요청·상한은 독점 예약이 아니고 실제 물리 용량 및 native 프로젝트 quota는 별도입니다.

요청 내용과 관리자 메모는 같은 도메인의 manager와 시스템 관리자가 볼 수 있으므로 사유에 비밀번호·토큰 등 비밀을 입력하지 마세요. 목록 조회에 실패하면 비어 있다고 판단하지 말고 다시 확인합니다.

관리자 Flavor의 **호스트·GPU 자동화 정책**에서 Nova 설정의 주 GPU alias와 오디오 등 동반 alias를 선택해 하나의 그룹 이름을 지정하고 명시 승인합니다. 이 이름은 새 `gpu.{그룹명}x{수}_{vCPU}c_{RAM}g` flavor와 도메인 pool에 함께 표시됩니다. 설정된 alias와 Placement가 보고한 장치·사용량은 별도이며 미확인 상태는0이 아닙니다. 여러 alias를 함께 요청해도 같은 물리 카드의 GPU/audio가 배정된다는 보장은 없습니다. 신규 장치는 자동 승인하지 않습니다. 호스트 단절·점검·목록 누락은 마지막 지원 사양을 지우지 않으며 관리자의 **호스트 제거**만 제외합니다. 제거 시 존재하는 Nova compute service를 disable하지만 VM을 삭제하지 않습니다. 다시 포함해도 native maintenance를 자동 해제하지 않습니다. 순간 용량 부족은 생성 가능 여부만 바꾸고 기존 flavor·VM은 유지합니다. Nova 소스 수정은 필요 없으며 실제 운영 반영·명시 활성화는 별도입니다.

사용자 VM 생성·검토·인스턴스 사양은 `4 vCPU · 32 GiB RAM`처럼 실제 자원량으로 표시하며 GPU는 확인된 모델·장 수를 함께 보여줍니다. Native flavor 이름이나 UUID를 찾아 선택할 필요가 없고, 사양을 확인할 수 없으면 미확인으로 표시합니다. 관리자 관리 화면과 Nova CLI의 원래 이름·ID, 이미 생성된 VM은 바꾸지 않습니다. 자동화가 켜지면 확인 가능한 기존·새 수동 CPU flavor도 관리 대상이고 private flavor의 도메인 프로젝트 접근이 변경될 수 있습니다. Public flavor는 Nova에서 계속 공개되므로 직접 Nova 요청은 Afterglow 정책을 우회할 수 있습니다.

### 인스턴스 목록 정렬과 페이지 이동

인스턴스 목록은 기본으로 최근 생성 순서입니다. Desktop에서는 **이름·상태·이미지/인스턴스 사양·IP·라이브러리·전략** 열 제목을 누르면 오름차순, 한 번 더 누르면 내림차순, 다시 누르면 기본 최신순으로 돌아갑니다. Mobile/tablet 카드 위의 **열 정렬** 버튼도 같은 순서이며 키보드로 실행할 수 있습니다. 정렬은 현재 필터에 맞는 전체 프로젝트 목록에 적용한 뒤 페이지를 나누며, 바꾸면 첫 페이지로 돌아가 선택을 해제합니다.

**페이지당 행**은 목록 아래 이전/다음 바로 옆에 있습니다. **튜토리얼**은 위쪽 **VM 생성** 옆에서 시작합니다. 충분히 넓은 desktop에서는 표와 작업 메뉴가 같은 폭 안에 들어가며 긴 IP와 라이브러리는 셀 안에서 줄바꿈합니다. 좁은 desktop 작업 공간의 표 스크롤과 mobile/tablet 카드의 상세·작업 메뉴는 계속 사용할 수 있습니다.

### VM 코어·메모리·GPU 직접 구성

**인스턴스 → VM 생성 → 직접 구성**은 항상 **GPU 없음·0장**에서 시작합니다. 먼저 코어와 RAM을 정하고 GPU가 필요하면 모델 검색 상자에서 이름을 검색해 선택하세요. 목록에는 현재 도메인·프로젝트와 선택한 CPU/RAM에서 사용할 수 있는 GPU만 표시합니다. CPU·RAM·GPU는 같은 컴퓨트 한 대의 현재 잔량과 프로젝트/도메인 quota를 함께 만족해야 하며 여러 호스트의 GPU를 더한 수가 한 VM의 최대 장 수는 아닙니다. 새 관측에서 현재 선택이 불가능해지면 값을 몰래 바꾸지 않고 오류를 표시하며 저장·진행을 막습니다.

코어·메모리·GPU 개수는 **숫자 칸에 직접 입력하거나 슬라이더를 움직여** 선택합니다. vCPU는 **2·4·6·8…128의 짝수**만 입력·선택할 수 있습니다(2의 거듭제곱만 허용하는 것은 아닙니다). 메모리는 GiB 단위이며 슬라이더 양 끝은 다른 선택값을 유지한 현재 최소·최대입니다. 창을 열 때 CPU/RAM과 GPU 모델·장 수별 가능 조합을 한 번 받아 이후 선택은 기다림 없이 브라우저에서 계산합니다. 수동·주기 새로고침은 전체 가용량을 갱신하고 저장·실제 생성은 서버가 다시 검사합니다. 숫자와 슬라이더는 함께 바뀌며 키보드 화살표·Home/End로도 조절합니다. 빈 칸·소수·홀수 vCPU·허용 범위 밖 값은 자동 보정하지 않고 저장·진행을 막습니다. 과거 홀수 초안은 짝수로 직접 고치거나 **최소 사양으로 다시 선택**(2vCPU·1GiB·GPU없음)으로 복구하세요. 기존1vCPU 등 native flavor·VM의 사양은 바꾸지 않습니다.

**구성 저장하고 계속**은 해당 사양을 저장하거나 정확히 같은 기존 사양을 재사용한 뒤 이미지 단계로 이동합니다. 이 동작만으로 VM이나 볼륨을 만들거나 자원을 예약하지 않습니다. **저장한 구성**에서 본인·현재 프로젝트의 이전 사양을 **다시 확인하고 사용**할 수 있고, **기존 사양**에서는 접근 가능한 기존 사양을 계속 고를 수 있습니다. 화면은 코어·RAM·확인된 GPU 모델과 장 수로 구분하며 내부 flavor 이름/ID는 요청 식별자로 유지합니다. 저장할 때와 실제 VM을 만들 때 현재 권한·quota·배치 가능성을 다시 검사하므로 이전 저장 사실이 현재 생성 가능을 보장하지 않습니다.

직접 구성의 진행 버튼은 창 아래 **구성 저장하고 계속** 하나입니다. 저장 중에는 중복 실행을 막고, 실패하면 입력과 현재 단계가 유지됩니다. 다른 관리 작업과 겹칠 때의 최대15초 잠금 대기와 전체 저장 응답 대기는 별개입니다. 저장 요청만 최대120초 기다리며 응답이 유실되면 같은 요청의 결과를 GET으로 최대120초 더 확인합니다. 원래 사양이 현재 권한·가용량 검사를 통과한 경우 자동 선택해 이미지 단계로 이어가며 같은 저장을 다시 보내지 않습니다. 이 시간은 완료 예상이나 성공 보장이 아닙니다.

코어·메모리 초안은 이 브라우저의 계정·프로젝트·사용자/관리자 화면별로 자동 보존합니다. 창을 닫고 다시 직접 구성을 시작하면 CPU/RAM은 복원하되 GPU만 없음으로 시작합니다. 이미 열린 창의 GPU 선택은 주기 새로고침이나 일반 자격 갱신 때문에 초기화하지 않습니다. 서버의 저장 구성·기존 flavor 선택은 별도이고, 결과 불명 저장의 원래 사양은 확인 전 보존합니다. 복원은 native flavor 저장·VM 생성을 실행하지 않으며 비밀번호·cloud-init·사용 일정 동의는 초안에 저장하지 않습니다. **새로 시작**은 초안을 지우지만 서버에 저장한 구성은 삭제하지 않습니다.

사양 자동화가 비활성/준비되지 않았거나 저장 결과를 확인할 수 없으면 명시 오류를 확인하세요. 자동화를 임의로 켜거나 같은 저장을 자동 재전송하지 않습니다. **저장 결과 새로 확인**은 원래 요청 식별자의 결과만 다시 조회하며 저장 목록이나 native 이름을 수동 검색할 필요가 없습니다. 결과를 확인하면 현재 권한·정책·실제 사양·가용량을 다시 검증해 기존 결과를 선택합니다. 빈 목록·결과 없음·미확인은 실패나 재저장 허가가 아니므로 원래 사양과 결과 불명 상태를 유지합니다. 계속 미확인이면 표시된 오류와 요청 시점·사양을 관리자에게 전달하세요.


## 인스턴스 사용 일정과 만료 알림

현재 source의 사용 일정은 **모든 GPU**, **12 vCPU 이상 또는 RAM64 GiB(65536 MiB) 이상**, 그리고 관리자가 추가 지정한 플레이버에 적용됩니다. 생성 wizard의 설정·검토 단계에서 종료 시각과 만료 동작을 확인하세요. 기본은 생성 준비 시점부터 **한 calendar month**이며30일 고정이 아닙니다. 해당 일이 없는 달은 월말로 맞춥니다. 화면은 local timezone, 서버 저장은 UTC입니다. 기본보다 늦은 첫 종료일에는 사유가 필요합니다. 기존 대상 VM은 과거 생성일에 소급하지 않고 **처음 일정을 성공적으로 등록한 때부터 한 달**의 유예를 받습니다.

인스턴스 상세의 **사용 일정**에서 상태·종료 시각·최근 오류를 확인하고 쓰기 권한이 있으면 미래 날짜와 사유로 연장할 수 있습니다. Reader는 조회만 가능합니다. 사유는 한 줄이며255 UTF-8 bytes 이내입니다(한글 등은 글자 수보다 byte 수가 큽니다). 최신 일정을 기준으로 저장하며 충돌/실패 후에는 새로고침하여 현재 상태를 확인하세요. 연장은 별도 관리자 승인 신청이 아닙니다. 완료/차단 일정을 연장해도 **VM이 자동 시작·unshelve되지는 않습니다**. Afterglow에서 다시 시작하기 전에 유효한 active 일정이 필요합니다. 작업 중/불명 상태는 운영자의 확인이 필요할 수 있습니다.

만료 전7일·3일·1일 구간의 in-app 경고와 전역 알림 bell에서 현재 프로젝트의 일정에 접근할 수 있습니다. 연체·진행 중·오류는 주의가 필요한 상태로 표시하고 해당 VM 상세의 일정으로 이동합니다. 확인된 대상0건과 조회 실패/손상 metadata로 **알 수 없음**은 다릅니다. 오류 표시를 알림0건으로 해석하지 마세요. 이는 이메일·push 발송이나 외부 전달 보장이 아닙니다.

기본 만료 동작은 **shelve 후 offload**입니다. `SHELVED_OFFLOADED`가 확인되기 전에는 compute 자원 반환 완료가 아닙니다. 선택한 **stop 후 삭제**는 되돌릴 수 없으며 root/data Cinder 볼륨은 기본 보존합니다. 별도 연결 디스크 삭제 동의를 켜야 검증된 연결 볼륨을 함께 삭제합니다. 이 동의는 소비자 소유의 단독 연결 lower clone 볼륨에도 적용될 수 있지만, 백업·스냅샷·Manila share·공개 원본 이미지/스냅샷·보호된 source artifact는 지우지 않습니다. Local ephemeral disk는 VM 삭제 시 사라집니다. 관리형 전용 접근 규칙·credential·네트워크 자원은 정확한 소유권 receipt에 따라 정리하고 보존 디스크 receipt와 필요한 원본 참조는 디스크가 실제 없어질 때까지 유지합니다. Legacy receipt가 없거나 attachment/소유권을 확인할 수 없으면 삭제가 차단되며 이름을 근거로 임의 정리하지 않습니다.

Background scheduler는 기본 비활성이고 운영자가 승인된 shared-Redis writer 환경에서 명시적으로 켜야 기존 VM 등록·만료 처리가 시작됩니다. Metadata 조회/설정 UI는 이와 별도로 사용할 수 있습니다. 활성 scheduler는 약60초 주기여서 종료 시각과 실제 처리 시각은 다를 수 있고 재시작 후 연체 일정을 다시 관찰합니다. 불명 native 요청을 자동 replay하거나 force 삭제하지 않습니다. 이 기능은 Nova metadata 기반 Afterglow 자동화이며 native metadata 편집 권한자의 CLI 우회를 막는 별도 Nova 강제 정책은 아닙니다. Source 구현이 운영 배포 완료를 의미하지 않습니다.

관리자는 Flavor의 전용 **추가 사용 일정 필수** 설정으로 더 작은 플레이버를 지정할 수 있습니다. 자동 관리 flavor에도 이 설정은 가능하지만 하드웨어·ACL 편집 잠금은 유지됩니다. 추가 지정을 해제해도 GPU·12 vCPU·64 GiB 기본 기준은 해제되지 않습니다.

## 인스턴스·볼륨 목록 정렬

사용자 모드와 관리자 모드의 인스턴스·볼륨 목록은 **생성일 최신순**으로 시작합니다. 목록 위 **정렬 기준**에서 최신순, 오래된순, 이름 오름차순, 이름 내림차순을 선택할 수 있습니다. 같은 화면에서 자동·수동 새로고침해도 선택한 정렬을 유지합니다. 생성 시각이 없는 자원은 날짜 정렬의 마지막에 표시합니다.

관리자 화면에서는 도메인·프로젝트·상태·이름 등 기존 검색 조건에 맞는 **전체 결과**를 정렬한 뒤 페이지를 나눕니다. 정렬을 바꾸면 첫 페이지로 돌아가며 기존 행 선택과 열린 상세는 해제됩니다. 좁은 화면의 카드 목록도 같은 순서와 선택 메뉴를 사용합니다.

## 목록·서비스 탐색·화면 모드

인스턴스·네트워크·볼륨은 제목과 짧은 요약 다음에 검색·필터·실제 목록을 표시합니다. 자동 새로고침은 한 선택 메뉴에서 끄거나 주기를 고르며, 수동 **새로고침**은 현재 검색 조건을 유지합니다. 관리자 범위 선택기의 **범위 목록 새로고침**은 도메인·프로젝트 선택지만 갱신하며 자원 새로고침과 다릅니다. 페이지와 페이지당 행 수는 목록 하단에 있습니다. 프로젝트 전체 응답의 화면 페이지와 관리자 네이티브 marker 페이지는 별개입니다.

인스턴스·네트워크 추이는 기본으로 접혀 있으며 **사용 추이 보기 / 네트워크 추이**에서 엽니다. 관리자 볼륨의 전체 도메인·용량 보고서는 **용량 분석**에 있고 기본 **리소스 목록**에는 자원 행을 먼저 표시합니다. 짧은 UUID 옆 복사 버튼으로 전체 값을 복사하고, 전체 값은 툴팁·복사 실패 안내에서도 확인합니다. 네트워크 행의 상세·수정·삭제는 작업 메뉴에 있습니다. 선택한 행이 있을 때만 일괄 작업을 표시합니다.

**모든 서비스**에서 서비스 이름이나 기능을 검색하고 별 버튼으로 즐겨찾기에 추가합니다. 즐겨찾기는 이 브라우저의 계정·모드별 표시 설정이며 권한을 부여하거나 프로젝트를 전환하지 않습니다. `Kubernetes · Drover`, `런타임 레이어 · Palimpsest`, `VPN · Waygate`, `AI 채팅 · Lumen`은 기능과 제품 이름을 함께 표시합니다. 설치 이름은 운영자 설정을 따르며 Afterglow는 콘솔 제품 이름입니다.

사이드바의 **모든 서비스**는 왼쪽 화살표가 있는 상위 탐색 행입니다. 전역 메뉴와 사이드바에는 VM 생성 버튼이 없으며 **인스턴스 페이지 → VM 생성**에서 만듭니다. 첫 인스턴스 안내와 VM 생성 튜토리얼도 이 경로를 사용합니다. 볼륨·DB 백업은 공통 보관함 아이콘으로 표시합니다.

**VM 메트릭**은 현재 프로젝트의 인스턴스 이름/UUID를 검색·선택해 CPU·메모리·네트워크·디스크의 실제 수집값을 봅니다. 컴퓨팅 노드의 node-exporter 합계가 아니며, 미수집은0이나 호스트 데이터로 바꾸지 않습니다. 대시보드는 조회 중·데이터 없음·부분 수집·오류에서도 같은 세 metric 영역을 유지하고, 자동 갱신 중 이미 확인한 빈 상태를 로딩 화면으로 되돌리지 않습니다.

상단 테마 메뉴에서 **라이트 모드 / 다크 모드 / 시스템 테마**를 직접 선택합니다. 체크가 현재 선택이며 시스템 선택은 현재 적용 결과도 안내합니다. 시스템 테마가 바뀌면 화면은 자동으로 따릅니다. 라이트 모드의 카드·표·편집 입력은 흰색, 읽기 전용·비활성 입력은 회색이며 포커스와 선택은 별도 표시됩니다. 상태는 색만이 아니라 점과 이름으로 표시하고 원래 기술 코드는 툴팁에 남깁니다.

관리자 **기본 설정**은 브랜딩·인프라 기본값·가입 정책·기본 쿼터·가입 요청으로 구분됩니다. 탭 전환은 저장이 아니며 가입 정책과 기본 쿼터의 저장은 같은 revision을 공유합니다. Palimpsest 관리자는 레이어 탐색에서 빌드 생성으로 이동해 실제 기반 이미지·봉인된 프로필 또는 기존 Dockerfile을 명시적으로 선택합니다. 프로필·아티팩트·빌드 기록·실행 인스턴스는 별도 탭에서 계속 관리합니다.

토폴로지의 전체 관리자 범위는 도메인·프로젝트 묶음에서 시작합니다. 묶음을 펼쳐 자원을 선택하면 기존 연결·상세 화면으로 이동합니다. 축소 화면은 작은 이름 대신 개수를 요약하며 선택한 직접 연결만 강조합니다. **연결 구조 애니메이션**은 기본으로 꺼져 있고 실제 패킷 관측이 아닙니다. 범례·도움말은 도구 모음에서 엽니다.

VM 생성에서 조회 실패는 사양 없음·검색 결과 없음과 다릅니다. 사양·호스트 용량을 확인할 수 없으면 재조회를 먼저 수행하며 다음 단계로 넘어갈 수 없습니다. 쿼터 부족은 필요한 자원과 남은 양을 별도로 안내합니다. Lumen 통계의 네이티브 권한 거부는 Afterglow 관리자 권한 회수와 같지 않으며 현재 인증/관측 범위와 Lumen 정책을 확인해야 합니다.


## 공개 소개 페이지의 제공 범위

`/`는 연구자·교수를 위한 **클라우드 서버, GPU 기반 AI 학습 환경, Lumen AI 채팅, Kubernetes 플랫폼**을 큰 제품 그림과 기능별 장면으로 소개합니다. 각 장면에는 한 문장 설명과 `/docs/nova`, `/docs/lumen`, `/docs/drover`의 사용 가이드가 있습니다. GPU·모델·사용 범위는 기관이 구성한 자원과 정책에 따라 달라집니다.

**기관 클라우드 구축** 장면은 서버·GPU·스토리지·네트워크가 내부 클라우드와 연구팀별 프로젝트로 연결되는 원리를 보여줍니다. 구축 문의는 이메일로, 제공 클라우드 이용은 기존 콘솔로 연결되며 실제 배포나 자원 이동을 수행하지 않습니다.

메인 페이지는 판·블록이 모이고 정렬되는 **키네틱 아트**로 기능을 설명합니다. 첫 화면의 네 서비스 탑, 서버 조립, GPU 핀, 컨테이너 배치, 기관 클라우드 적층은 화면에 들어오면 한 번 움직이고 완성된 구조로 멈춥니다. 연결선은 조형이 자리를 잡은 뒤 나타나며, 화면 밖·숨겨진 탭에서는 일시 정지합니다. 다시 보기 버튼은 해당 장면만 재생합니다. Lumen은 ‘대화 예시’로 표시한 질문과 답변을 읽을 수 있게 순서대로 보여줍니다. 실제 사용자 기록·실시간 AI 실행·자원 생성은 하지 않습니다. 모션 감소 설정과 JavaScript/observer 없는 환경에서는 완성된 그림과 대화 전체를 바로 읽을 수 있습니다. Palimpsest의 실행 레이어 기록·저장·포크·재사용은 제공 서비스로 홍보하지 않습니다.

## 지원 언어

전체 가이드는 한국어, 영어, 일본어, 중국어 간체, 스와힐리어(탄자니아), 노르웨이어 보크몰, 말레이어(말레이시아), 베트남어, 벵골어(방글라데시)로 읽을 수 있다. 문서 헤더의 언어 메뉴에서 선택하며 본문·탐색·검색·목차·명령 복사·오류 안내가 함께 바뀐다. 추가 언어 번역은 원어민 검수 전 초안이다.

|---|---|---|

| English | `/docs?lang=en` | `/docs/manila?lang=en#mount` |
| 日本語 | `/docs?lang=ja` | `/docs/manila?lang=ja#mount` |

문서·메인·로그인·콘솔은 같은 테마형 메뉴와1년간 유지되는 `afterglow_locale` 쿠키를 사용한다. 유효한 명시적 `lang`은 쿠키보다 우선하고 실제 문서 탐색에서 공용 선호를 갱신한다. 언어 없는 문서·지원하지 않는 `lang`은 저장된 유효한 쿠키를 따르며, 둘 다 없으면 한국어다. Preload는 선호를 바꾸지 않는다. 브라우저 언어에 따른 자동 redirect·계정 언어 저장은 하지 않는다. 공유할 때는 한국어도 포함하여 `lang` query를 명시한다. 최초 SSR과 client navigation의 문서 언어를 모두 설정한다. 언어 링크는 JavaScript 없이도 현재 문서·기존 query를 유지하며, hydration 뒤에는 목차 fragment도 유지한다. 문서 내부 링크는 선택 언어와 튜토리얼 context를 유지한다. 메뉴는 방향키·Home/End·Enter·Escape와 밖 클릭·Tab 이탈을 지원하며 앱 항목은 Space도 지원한다.

검색은 선택 언어의 전체 본문과 키워드를 대상으로 한다. 명령의 API·상태·환경변수·필드·경로와 최종 code bytes는 모든 언어가 공유하며 실행 예시 placeholder와 필수 변수 진단은 중립적인 영어를 쓴다. 실제 한국어 콘솔 버튼을 찾기 위해 일부 번역 문장에서 원래 UI 이름을 번역 뒤 괄호에 함께 표시한다.

| `/docs/barbican` | 비밀 값 생성·조회·삭제와 자격 보호 |
| `/docs/drover` | Kubernetes 클러스터·노드·kubeconfig·워크로드 |
| `/docs/waygate` | WireGuard 게이트웨이·클라이언트·설정·연결 |
| `/docs/lumen` | AI 채팅·Studio·모델·한도·API/CLI 연결 |
| `/docs/palimpsest` | 프로젝트 패키지·접근 키·불변 레이어 재사용 |
| `/docs/mcp` | 외부 AI의 인바운드 MCP OAuth·개인 키·접속 확인과 Lumen 아웃바운드 연결의 구분 |

각 가이드는 준비 사항, 작업 순서, 결과 확인, 정리·데이터 손실 주의, 장애 대응, 관련 문서와 콘솔 링크를 제공한다. 일부 작업은 UI가 아닌 외부 CLI 예시임을 본문에서 구분한다. 명령은 복사할 수 있으며 실제 환경의 이미지·사용자·ID·IP·파일 경로로 바꾸어 실행한다. 문서를 열거나 명령을 복사하는 것만으로 실행되지는 않는다.

## 실제 화면으로 절차 확인하기

15개 가이드의 세부 절차에 실제 콘솔 화면 42장을 배치한다. 로그인·프로젝트 선택, 생성 전 폼, 자원 목록·상세, Studio·MCP 설정 위치를 본문에서 대조할 수 있다. 각 그림은 번역된 대체 텍스트·설명과 한국어 화면·개인정보 가림 안내를 제공한다. 그림 아래의 **원본 이미지 열기 (새 탭)**를 눌러 확대하고 모바일에서는 작은 버튼·입력값을 읽는다.

캡처는 당시 실제 배포의 상태이며 문서의 테마를 바꾸어도 사진의 테마는 바뀌지 않는다. 배포 버전·서비스 설정·권한에 따라 화면이 다를 수 있다. 접근 거부·베타 제한·빈 목록은 그 상태로 설명하며 성공 화면으로 꾸미지 않는다. 특히 Palimpsest 캡처는 관리자 identity 접근 거부, Octavia 상세는 본문의 HTTP 예제와 다른 기존 TCP 구성이다.

사진에는 사용자·프로젝트 이름, 자원 식별자·IP, 대화 제목·개인 키 이름 등 불필요한 실제 정보를 남기지 않는다. 공개되는 원본 WebP 자체에서 해당 픽셀을 제거하며 CSS 가림만으로 보호하지 않는다. 실제 키 발급·비밀 조회·유료 호출·자원 생성/삭제를 캡처 준비 단계로 실행하지 않는다. 발견한 시각 문제와 검증 범위는 [화면 캡처·시각 점검 기록](user-guide-visual-review.md)에 남긴다.

## 계정과 내 리소스

- 계정 설정은 **프로필 → SSH 키 → Beta 기능 → 세션 → MCP → 활동** 순서의 왼쪽 메뉴로 이동한다. 태블릿·데스크톱은 사이드바를 접어 아이콘 메뉴로 사용할 수 있고 모바일은 상단 전체 메뉴에서 **계정 설정**을 연다. 선택한 항목은 주소에 남아 새로고침·뒤로/앞으로 이동·직접 링크에서도 유지된다. 프로필(`/dashboard/account`)에는 사진·이름·이메일·비밀번호·로그인 작업 공간 설정이 있다. SSH 키는 `/dashboard/account/keypairs`, Beta는 `/dashboard/account/beta`, 로그인 세션은 `/dashboard/account/sessions`, MCP는 `/dashboard/account/mcp`, 최근 활동은 `/dashboard/account/activity`에서 관리한다.
- 우측 상단 프로필 사진을 누르면 `/dashboard/account`를 연다. **프로필 사진**에서 현재 이메일의 **Gravatar 사용**, **아바타 생성/다른 아바타 생성**, **사진 업로드**를 선택한다. 저장 즉시 상단과 프로필에 같이 반영되고 새 로그인에도 유지된다. Gravatar는 이메일 해시를 외부 서비스에 보내며 생성·업로드는 외부 이미지 요청이 없다. 정지 PNG/JPEG/WebP/GIF만2MiB·4096px·4백만 픽셀 이내로 올릴 수 있고128px 정사각형 PNG로 저장된다. 지원하지 않는 파일은 기존 사진을 바꾸지 않는다.
- 기존 로컬 비밀번호가 있는 사용자는 프로필에서 현재 비밀번호와 새 비밀번호·확인을 입력해 변경한다. 서버는 원래 계정 소속의 본인 현재 비밀번호를 검증하고 Keystone self-service `POST /v3/users/{id}/password`를 한 번 호출한다. 현재 비밀번호 거절은 로그아웃 없이 폼에 표시한다. 성공 또는 결과 불명확 시 비밀번호 입력과 로컬 로그인을 지우고 로그인 화면으로 이동한다. 자동 재전송하지 않으며 결과를 확인하지 못했다면 기존 또는 새 비밀번호로 로그인해 확인한다.
- 비밀번호를 잊었다면 프로필의 **비밀번호를 잊으셨나요?**로 현재 등록 메일에 **새 비밀번호 입력 폼의 일회용 링크**를 요청한다. 메일에서 직접 새 비밀번호를 정하며, 이 셀프 복구 메일에는 비밀번호 자체를 넣지 않는다. 접수 표시는 실제 발송·받은편지함 수신 확인이 아니므로 메일을 받지 못하거나 메일함에 접근할 수 없으면 관리자에게 문의한다. 외부/매핑 계정도 기존 native password가 실제 존재하면 복구할 수 있으나 무비밀번호 계정의 최초 생성 본인 증명을 우회하지 않는다.
- 셀프 비밀번호 메일 복구는 로컬/외부 계정 모두 **native API v2가 기존 비밀번호 이력과 계정 revision을 확인**해야 발급한다. 계정 종류 표시나 marker가 없어도 이 검사를 생략하지 않으며, 확장 불가·이력 없음이면 같은 접수 안내만 보이고 메일은 발급되지 않는다. 기존 구형 링크는 만료될 수 있으므로 관리자에게 문의한다. 현재 비밀번호를 아는 사용자 변경과 위임된 관리자 난수 재설정은 이 메일 복구 제한과 별개다.
- 관리자 **Identity → 사용자 → 수정 → 난수 비밀번호 재설정 및 메일 전송**은 현재 등록된 유일한 메일을 확인한 후 기존 password를32자 난수로 바꾸고 그 password를 자동 메일로 보낸다. 수신 주소는 편집 중인 임의 주소가 아니며 서버가 현재 native 계정에서 재확인한다. 실제 password가 메일함에 남으므로 링크 복구보다 위험하며, 사용자는 로그인 직후 자신의 비밀번호로 변경해야 한다. 강제 첫 로그인 만료 기능은 없고 native password 정책은 유지된다. 검증된 STARTTLS가 없으면 변경 전 차단한다. 메일 실패라도 이미 변경됐을 수 있으므로 창의 `변경됨/전달 실패/세션 회수 실패/감사 실패/결과 불명` 안내를 읽고 자동 재요청하지 않는다.
- 외부 로그인 계정의 **패스워드 생성하기**는 서버가 사용 가능하다고 확인한 경우에만 표시된다. 이 기능은 별도 **Keystone 28.1.0 최초 비밀번호 확장**의 설치·스키마·native qualification이 필요하며, 이 안내는 소스 구현에 대한 설명이지 운영 배포·실서비스 수용 확인이 아니다. 사용할 수 없다고 나오면 **사용 가능 여부 다시 확인** 또는 관리자에게 계정 정책·메일 설정·확장을 문의한다. [배포 선행 조건](deployment.md)과 [Profile API](api/profile.md)를 참고한다.
  1. 프로필에서 **로컬 비밀번호는 로그인 제공자(IdP)의 MFA나 계정 비활성화 정책을 우회할 수 있다**는 경고를 읽고, 이 차이를 이해한 경우에만 **패스워드 생성하기**를 누른다. 계정에 등록된 유일한 이메일로 **1시간 만료 일회용 링크**를 보내며, 발송 완료는 아직 비밀번호가 생성되지 않았다는 뜻이다.
  2. 이메일 링크를 열고 **로그인 제공자로 다시 로그인**을 선택해 요청한 것과 **같은 계정**으로 SSO 로그인한다. 같은 탭에서 완료하면 링크로 돌아온다. 탭에 안전하게 이어가기를 보관할 수 없다면 로그인한 뒤 이메일 원래 링크를 같은 탭에서 다시 연다. 비밀번호는 브라우저 저장소에 보관하지 않는다.
  3. 서버는 이메일 증명 발급 **뒤에 시작된** 유효한 외부 로그인 세션이며 완료 시점으로부터 **15분 이내**인지 확인한다. 계정·원래 소속·등록 이메일·native identity 변경 여부와 현재 provider 정책도 다시 확인한다. 이는 Afterglow/provider 왕복의 최근성이지 IdP 비밀번호 재입력이나 MFA 수행·최근성의 보장이 아니다. 새 비밀번호(12–1024자, 추가 native 정책/byte 제한 적용)와 확인을 입력해 **확인하고 패스워드 생성**을 누른다. 기존 비밀번호 이력이 있으면 덮어쓰지 않는다.
  4. 성공 뒤에는 로그인 상태를 지우고 다시 로그인을 안내한다. 이미 비밀번호가 있거나 계정 정보·비밀번호 정책 때문에 native에서 거절한 경우에도 제출한 링크는 소비되므로 같은 링크를 다시 보내지 않는다. 계정 변경·정책 거절은 안내에 따라 프로필에서 새 확인 메일을 요청한다. 결과 불명확은 자동 재시도하지 않고 관리자에게 결과 확인과 잠금 정산을 요청한다. **생성됐지만 세션 회수 실패** 안내라면 다른 세션이 계속 활성일 수 있으므로 관리자가 남은 세션을 폐기해야 하며 생성 자체를 다시 시도하지 않는다.
  - 이 프로필·이메일 링크·재로그인 안내 여정은 한국어·영어·일본어·중국어 간체·벵골어·말레이어·노르웨이어 Bokmål·스와힐리어·베트남어의9개 UI locale에서 제공한다. 이메일 본문의 언어가 모두 현지화되었다는 뜻은 아니다.
- 관리자가 만든 Accounts 계정은 첫 성공한 로그인에서 개인 프로젝트를 준비한다. 안전하게 중단되면 화면 안내에 따라 비밀번호를 다시 입력해 **개인 작업공간 준비 재시도**를 누른다. 계정·기존 자원은 초기화하지 않는다. 이미 보낸 native 작업의 결과가 불명한 경우에는 반복 로그인으로 재전송하지 않으며 운영자의 종료 확인·settlement가 필요하다.
- `/dashboard/account/mcp`의 외부 AI 접근은 OAuth/API 키를 나란히 선택하며 선택한 방식의 설정·목록만 표시한다. API 키는 이름·읽기/관리 권한·1일/1주/1달/3달/6달/1년/만료 없음/직접 선택을 지정한다. 만료 없음도 명시적으로 폐기할 수 있으며 OAuth 위임의 유한 만료 정책은 바뀌지 않는다. 각 설정의 전체 `mcp.json`을 복사하고 실제 secret이 포함된 설정은 발급 직후에만 보관한다.
- 최근 활동은10/15/20개씩 이전·다음 페이지로 이동한다. 필터·새로고침·사용자/프로젝트 변경 시 오래된 응답과 페이지 위치를 새 범위에 섞지 않는다.
- `/dashboard/my-resources`는 접근 가능한 프로젝트의25종 지원 자원을 표시한다. DB·Drover·Waygate·파일/객체 스토리지·패키지·비밀 메타데이터도 포함하며 API 권한을 추가로 부여하지 않는다. 미지원/거부/장애는0개가 아니라 해당 상태·부분 합계로 표시한다. 다른 프로젝트 자원은 그 프로젝트로 전환한 뒤 열고, 사용자 범위 keypair는 합계에서 중복 제거한다. 가로로 긴 프로젝트 표는 포커스 후 방향키로 스크롤할 수 있다.
- 일반 VM 생성은 **사양 → 이미지/기존 부팅 볼륨 → 설정 → 검토** 순서다. GPU 사양에는 검증된 명시적 vendor/driver metadata의 이미지를 추천하고 CPU는 일반 이미지를 우선한다. 추천은 강제가 아니며 사양 변경 시에도 선택 UUID를 자동으로 교체하지 않는다. 비동작 HA와 공개 squashfs/library consume 선택은 제거했으며 관리자 Palimpsest·프로젝트 패키지·독립 파일 스토리지 카탈로그는 별도 기능이다.
- 사양은 Public/Private·CPU/GPU 모두 현재 프로젝트 quota를 확인합니다. Private만 별도의 native project access도 필요합니다. 생성 시 정상·스케줄링 허용 호스트 하나의 CPU/RAM/GPU 잔여량과 VM당 최대치를 함께 통과한 선택지만 보이며, 목록은 예약이 아니므로 최종 생성은 Nova가 다시 결정합니다. 새로 부족해진 선택은 자동 대체하지 않습니다.
- Native 암호 주입을 지원하는 Cloudbase Windows 이미지/부팅 볼륨은 설정 단계에서 초기 비밀번호와 확인값을 입력한다. 로그인 계정은 metadata에서 표시하고 입력값은 Nova `adminPass`와 강제 ConfigDrive로 전달한다. PowerShell/user-data·SSH 키·생성 후 암호 초기화는 필요 없다. 미지원 Windows는 SSH로 fallback하지 않고 생성 전에 차단한다. GPU flavor도 선택할 수 있지만 Linux GPU 초기화는 실행하지 않으며 Windows GPU 드라이버와 실제 GPU 사용은 별도로 확인한다. Nova 게스트 metadata/config drive의 비밀번호는 암호화되지 않으므로 접근을 보호한다. 최초 초기화는 약20–30분 걸릴 수 있고 ACTIVE/API 완료는 로그인 준비가 아니며 첫 RDP 프로필 준비에도 시간이 필요하다. RDP `TCP/3389`는 승인 원본에만 개방한다. 이미 초기화된 Windows 디스크의 재사용은 초기 암호 재적용을 보장하지 않는다.
- 이미지 소유자 또는 관리자는 사용자/관리자 이미지 상세의 **Windows 설정 → Windows 메타데이터 설정**에서 계정·실제 게스트 준비 확인과 선택 Win11/QGA 플래그를 검토해 한 번에 저장한다. 기본5개 값과 Cloudbase-Init·ConfigDrive·봉인·드라이버·RDP 선행 조건은 [Images API](api/images.md#브라우저의-windows-설정)와 공개 `/docs/glance`의 네 언어 안내를 따른다. 이전 `cloudbase-user-data` 게스트를 marker로만 전환하거나 저장을 신뢰/운영 승인으로 해석하지 않는다.
- 새 이미지 부팅의 루트 디스크는 실제 `min_disk` 이상이어야 한다. 예를 들어80GB 이미지에는80GB 이상을 사용한다. 선택/지연 metadata 로딩 때 작은 초안만 올리고500GB 같은 더 큰 초안은 유지하며 부족한 정수 크기는 다음/최종 제출에서 차단한다. 기존 볼륨 재사용에는 이 새 디스크 초안이 적용되지 않는다.
- 새 부팅 볼륨 용량 옆에서 **자동 스냅샷 활성화**, **자동 백업 활성화**를 각각 선택한다(기본 꺼짐). 켠 정책마다03:00 UTC, 일별2·주별2(월요일)·월별1(1일)을 보존하며 겹친 시각에는 월별>주별>일별 한 개만 만든다. 추가 스토리지/쿼터와 실행 중 강제 사본의 파일시스템·애플리케이션 일관성 제한을 확인하고 별도 동의해야 다음/생성이 가능하다. 스냅샷은 원본과 같은 스토리지에 있어 독립 백업 대체가 아니다. 기존 부팅 볼륨 재사용에서는 기존 정책을 변경하지 않는다.
- 인스턴스 보관·삭제는 쓰기 권한이 있는 정확한 SHUTOFF 상태에서, 리사이즈는 실행 중(ACTIVE)·정지(SHUTOFF) 상태에서 제공한다. 리사이즈는 VM 생성과 같은 직접 구성·저장 구성·카탈로그 선택을 쓰고, 실행 중이면 guest가 재시작된다. 완료 후 '리사이즈 확인' 또는 '되돌리기'를 선택한다. 정지해도 compute 할당·쿼터는 유지되며 보관 offload 완료 또는 삭제로 host compute를 반환한다. 보관 후 instance/retained-volume 사용량과 클라우드 집계에 따른 CPU/RAM 쿼터를 따로 확인한다. Windows SSH/keypair 표시는 실제 boot metadata로만 감춘다.
- 인스턴스 파일 스토리지 연결은 NFS fixed IP 또는 UUID-bound CephX 접근 허용이다. 실제 상태·export·share network를 보고 게스트에 직접 연결한다. 명시적으로 조회한 Ceph 키는 현재 패널에서만 보관하며 패널 닫기는 provider 키 회수가 아니다. 관리되는 정확한 규칙의 회수가 미완료이면 VM 삭제도 중지한다.
- 연결 root/data 볼륨은 모든 소유 VM을 정지한 뒤 더 큰 정수 용량으로 확장한다. Cinder의 실제 크기/status를 확인하고 게스트 디스크 감지·파티션/파일시스템 성장은 별도 절차로 검증한다. 화면은 비동기 extending 중 요청 용량을 완료 값으로 표시하지 않는다.
- **주기적인 볼륨 백업**은 `볼륨 → 볼륨 백업 → 자동 백업 설정` 또는 볼륨 목록·상세의 같은 설정 메뉴에서 만든다. 원본·HH:mm/IANA 시간대·일/주/월 보존·주별 요일/월별 일자를 지정하고 활성화해 저장한다. 저장 즉시가 아니라 다음 예정 시각부터 실행되며0보존은 해당 주기를 끈다. 사용 중 볼륨의 강제 백업은 저장 일정 전체에 대해 별도로 동의해야 하며 데이터 일관성·복원은 보장하지 않는다. 정책 카드에서 다음/최근/결과/백업ID를 확인하고 편집·일시 중지·재개·제거한다. 정책 제거는 기존 백업을 삭제하지 않는다. `/docs/cinder`의 백업 절차와 [API 계약](api/volumes.md#6-자동-백업)을 함께 확인한다.
- 계정·내 리소스·일반 콘솔 페이지는 같은80rem 최대 폭의 가운데 정렬 외부 박스를 사용한다. Lumen 채팅·채팅 프로젝트는 예외로 전역 header와 서비스 메뉴를 제외한 작업 영역 전체를 채운다. 새 채팅의 짧은 입력창은48rem,160자 이상 또는3줄 이상 초안과 기존 대화의 입력창·기록은80rem 상한이다. 프로젝트·기록 전환은 현재 초안·스크롤을 유지하며 이전 기록은 스크롤로 불러온다. 모바일에서는 가용 폭을 사용하고 표·코드는 자신의 영역에서 스크롤한다.

## 접근 및 표시 경계

- `/docs`와 `/docs/` 아래 경로만 공개 문서 범위다. `/docsevil`·`/docs-admin` 같은 유사 접두 경로의 인증 조건은 바꾸지 않는다.
- 미등록 서비스 문서는 404와 문서 홈 안내를 유지한다. 로그인 상태라는 이유로 문서 404를 SPA 홈 200으로 바꾸지 않는다.
- 공개 문서는 로그인 세션의 프로젝트 선택·인증 복구 화면을 요구하지 않고 인증 갱신·공지 polling을 시작하지 않는다. 이전 콘솔 요청이 세션 만료로 실패해도 현재 문서에서 로그인 화면으로 이동하지 않는다. 기존 보호 콘솔의 인증·프로젝트 검사는 유지한다.
- 문서 내용은 서비스 활성화와 관계없이 읽을 수 있다. 선택 서비스의 하단 콘솔 링크는 현재 공개 site-config의 서비스 gate를 반영한다. API 권한 검사는 여전히 백엔드가 소유한다.
- 튜토리얼에서도 문서 진입이 허용되며 문서 내용을 가상 자원 응답으로 대체하지 않는다. 콘솔 복귀는 기존 튜토리얼 범위를 유지한다.
- 모바일은 문서 메뉴·목차를 inline disclosure로 제공하고, tablet은 서비스 문서 탐색 열, desktop은 문서 내부 목차 열을 추가한다. 코드의 가로 스크롤은 해당 영역 안으로 제한한다.
- Key Manager에서 이미 표시한 비밀은 다른 값 조회가 진행 중이어도 즉시 숨길 수 있다. 새 값 조회는 직렬화하지만 숨기기는 로컬 동작이므로 네트워크 완료를 기다리지 않는다.

## 내용 수정 위치

사용자 문서 정본은 `frontend/src/lib/docs/`의 typed static data다. 같은 내용을 별도 Markdown·HTML 엔진에 복제하지 않는다.

- `types.ts`: guide·section·step·command·link와 `DocScreenshot` (`src`, `alt`, `caption`, `width`, `height`) 계약.
- `gettingStarted.ts`: 프로젝트 시작 절차.
- `iamGuide.ts`: 사용자별 IAM·manager·프로젝트 및 서비스 역할의 상세 정본.
- `coreGuides.ts`: Nova·Neutron·Octavia·Cinder·Manila.
- `additionalGuides.ts`: Glance·Object Storage·Trove·Barbican.
- `platformGuides.ts`: Drover·Waygate·Lumen·Palimpsest.
- `catalog.ts`: 전체 목록, 선택 언어 catalog의 lazy load/cache와 검색 인덱스.
- `paths.ts`: 정확한 공개 문서 경로 판정.
- `locales.ts`: 지원 언어·URL context·번역된 shell/index/article/copy/error 문구와 카테고리.
- `mcpGuide.ts`: 외부 AI의 인바운드 MCP OAuth·개인 키·연결 확인과 권한·만료·회수 경계.
- `translate.ts`: reader-facing 필드 변환; 누락·빈 번역은 오류로 처리하고 한국어 본문으로 조용히 fallback하지 않는다.
- `translations/{en,ja,zh-CN,sw,nb,ms,vi,bn}/`: 언어별 guide group dictionary. source literal key를 유지하고 한국어 정본 변경 시 모든 번역 언어의 해당 항목도 함께 갱신한다. slug·section ID·link URL·service gate·related slug·실행 code는 번역 대상이 아니다.
- `frontend/src/routes/docs/`: 공개 shell·목록·서비스 article·404 화면.
- `frontend/src/lib/components/docs/DocScreenshot.svelte`: section/step 그림의 공통 figure·대체 텍스트·설명·원본 링크·반응형 표시.
- `frontend/static/docs/screenshots/`: 개인정보를 제거한 공개 WebP. 한국어 정본의 `screenshots`에 연결하고 alt·caption 변경은 모든 번역 dictionary에 함께 반영한다. 경로·원본 크기는 번역하지 않는다.

본문은 Svelte text node로 escape되며 raw HTML을 주입하지 않는다. 외부 URL·내부 콘솔 링크·명령을 추가할 때 현재 route/component/API를 확인하고 실 credential, 운영 내부 주소, 개인 데이터를 예시에 넣지 않는다. 서비스의 API 계약은 [API 참고 자료](api-reference.md), 시각 계약은 [디자인 시스템](https://github.com/openstack-afterglow/openstack-afterglow/blob/dev/DESIGN.md)을 따른다. 사용자 문서 변경만으로 API 실행·데이터 플레인·운영 배포 성공을 기록하지 않는다.
